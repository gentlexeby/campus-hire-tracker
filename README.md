# 秋招进度板（Campus Hire Tracker）

一款面向个人和少量体验者的本地优先求职管理工具。它以“岗位申请”为主线，帮助你集中管理申请阶段、下一步行动、等待事项、面试日程和申请备注。

这个仓库也是一个 **AI 辅助全栈开发学习项目**：优先把真实可用的小功能做完整，练习从需求取舍、数据库迁移、文件上传、前后端交互、测试到 GitHub 分发的完整链路，而不是把个人工具提前做成 SaaS。

应用当前以 Windows 本地版本运行：不需要注册账号，不依赖云端数据库，也不会默认上传求职数据。正式数据按 Windows 用户保存在各自电脑上；同一 Windows 账号下的多个源码副本会共用这份数据。

> 当前为内部 Alpha，适合个人试用和反馈，不应把它当作唯一的数据备份。

## 快速开始

已经安装 Git 和 Node.js 24 的 Windows 11 x64 用户，可以直接执行：

```powershell
git clone https://github.com/gentlexeby/campus-hire-tracker.git
cd campus-hire-tracker
git switch codex/resume-library-mvp
.\setup.cmd
.\start.cmd
```

保持最后一个命令窗口开启，并访问 <http://127.0.0.1:3210>。上面的 `codex/resume-library-mvp` 是已通过自动化验收的简历版本库预览分支；它尚未合并到 `develop`。更看重稳定性时改用 `main`，只想体验已合并的开发功能时改用 `develop`。如果电脑上已经有真实数据，请先按[人工备份](#当前阶段的人工备份)复制整个数据目录，再首次启动该功能分支。

## 可以做什么

当前稳定核心功能包括：

- 创建和编辑岗位申请，记录公司、岗位、招聘批次、地点、来源和优先级
- 在机会池、准备投递、已投递、测评 / 笔试、面试中和 Offer 等阶段之间人工推进
- 为活跃申请设置“有下一步”“等待中”或“待补下一步”
- 记录面试、笔试、测评、投递截止、行动截止和复查事件
- 在“今日”页面查看逾期、近期事项、等待复查和缺少下一步的申请
- 检测重复申请、日程冲突和并发修改
- 归档被拒绝、主动放弃或撤回的申请，并在需要时恢复
- 查看不可直接编辑的申请时间线

`develop` 分支还包括：

- 申请备注及浏览器临时草稿恢复
- 单个事件、当前日程列表和全部未来事件的 ICS 导出
- 导出前逐项预览，以及预览内容变化后的安全拒绝
- 默认排除普通备注等敏感正文的日历导出边界

已通过自动化验收的 `codex/resume-library-mvp` 分支在 `develop` 的基础上增加：

- 建立个人简历库，并按时间保留多个文件版本
- 每个版本可保存 DOCX 源文件、PDF 投递文件或两者；单文件最大 10 MiB
- 在浏览器中预览 PDF、下载 DOCX，并归档暂时不用的简历
- 为一条岗位申请选择确切的 PDF 简历版本，之后可以回看当时投递的是哪一版

这一版不在应用内编辑简历版式或正文，也不提供 AI 简历优化。推荐先用熟悉的外部工具修改，导出 DOCX/PDF 后上传为新版本。

## 版本与分支

| 版本 | 用途 | 内容 |
| --- | --- | --- |
| `m1-a` 标签 | 固定稳定快照 | 个人求职推进核心闭环 |
| `main` 分支 | 稳定开发基线 | 与 M1-A 稳定功能保持一致，可能包含后续文档修订 |
| `develop` 分支 | 最新开发版本 | 稳定核心功能，以及备注草稿恢复、ICS 导出等后续能力 |
| `codex/resume-library-mvp` 分支 | 简历功能预览 | `develop` 的能力，以及简历文件版本库和岗位申请关联；合并前不视为稳定版 |

只想体验最稳定的核心流程时使用 `main`；想使用已合并的最新功能时使用 `develop`；想提前体验简历版本库时使用 `codex/resume-library-mvp`。

> 简历功能分支首次打开旧数据库时会把 schema 从 v1 前向升级到 v2。当前不支持降级；升级后再让 `main` 或 `develop` 读取同一份真实数据可能被安全拒绝。评估分支时建议先备份，或按“开发模式”一节使用独立的 `.test-data` 数据目录。

## 安装

### 1. 环境要求

- Windows 11 x64；Windows 10 尚未完成正式验证
- [Git for Windows](https://git-scm.com/download/win)
- [Node.js 24 LTS](https://nodejs.org/en/download)，以及随其安装的 npm（本仓库当前使用 npm 11）
- 当前维护版 Microsoft Edge 或 Google Chrome
- 能访问本仓库和 npm 软件包源

检查版本：

```powershell
git --version
node --version
npm --version
```

`node --version` 应显示 `v24.x.x`。当前 Alpha 不支持直接使用其他 Node.js 主版本。

### 2. 克隆仓库

这是公开仓库，通过 HTTPS 克隆不需要接受邀请，也不需要把 GitHub Personal Access Token 写入克隆地址。只有向仓库推送代码时才需要相应权限。

```powershell
git clone https://github.com/gentlexeby/campus-hire-tracker.git
cd campus-hire-tracker
```

选择稳定核心版本：

```powershell
git switch main
```

选择包含最新功能的开发版本：

```powershell
git switch develop
```

提前体验尚未合并的简历版本库：

```powershell
git switch codex/resume-library-mvp
```

### 3. 初始化

在仓库目录中双击 `setup.cmd`，或者在 PowerShell 执行：

```powershell
.\setup.cmd
```

初始化脚本会：

1. 检查 Node.js 运行环境；
2. 按 `package-lock.json` 安装固定版本依赖；
3. 在隔离临时目录检查本地 SQLite/libSQL 运行能力；
4. 创建生产构建。

第一次安装可能需要几分钟。看到下面的提示表示完成：

```text
[setup] Setup completed. Run start.cmd to launch the app.
```

初始化不要求管理员权限，也不需要 Docker、独立数据库或云端账号。
正式个人数据库会在首次启动并访问应用时创建，不是在 `setup.cmd` 的临时数据库检查中创建。

## 启动与停止

双击 `start.cmd`，或者执行：

```powershell
.\start.cmd
```

保持命令窗口开启，然后在浏览器访问：

<http://127.0.0.1:3210>

- 应用只监听本机回环地址，局域网中的其他设备不能直接访问。
- 在窗口中按 `Ctrl+C`，或关闭运行 `start.cmd` 的窗口，会停止应用，但不会删除已保存的数据。
- 如果提示端口 `3210` 已占用，请先关闭之前打开的应用窗口或其他占用该端口的程序；应用不会静默改用其他端口。
- 如果提示缺少生产构建，请重新运行 `setup.cmd`。

## 使用说明

### 1. 创建第一条申请

打开应用后进入“申请”，选择新建申请。最少只需填写公司和岗位。招聘批次、优先级、地点、来源及来源链接可以稍后补充。新申请默认进入“机会池”，优先级默认为“中”。

### 2. 记录当前进度

主阶段由你确认和修改，系统不会因为一次面试结束就擅自推进申请。建议在实际收到通知或完成节点后手动更新阶段。

每条活跃申请还应选择一种当前推进方式：

- **有下一步行动**：例如“今晚修改简历”，可以设置截止时间。
- **等待中**：例如“等待 HR 回复”，必须设置复查时间，避免无限等待。
- **待补下一步**：暂时还没想好下一步，申请会明确进入“缺少下一步”队列。

申请列表同时提供看板、表格、搜索以及阶段、优先级和推进方式筛选，便于快速找到需要处理的记录。

### 3. 每天查看“今日”

“今日”页面用于回答“我现在最需要做什么”。建议每天打开一次，依次处理：

1. 逾期或冲突事项；
2. 今天需要处理的行动和日程；
3. 未来七天即将发生的事项；
4. 到期需要复查的等待状态；
5. 尚未设置下一步的申请。

### 4. 安排面试和截止日期

可以从申请详情或“日历”页面创建事件。支持定时事件和全天事件，结束时间可以留空表示一个时间点。

当新事件与已有日程冲突时，应用会展示冲突摘要；只有明确确认后才会继续保存。事件完成或取消不会自动改变申请主阶段。

当前界面支持创建、标记完成和取消事件，尚未提供事件改期、编辑或删除入口。

### 5. 记录申请备注

`develop` 分支可以在申请详情记录备注。输入内容会临时保存到当前浏览器的 IndexedDB，用于意外刷新后的恢复。

请注意：

- 浏览器草稿不等于正式保存；完成编辑后仍要点击保存按钮。
- 正式保存失败或版本冲突时，草稿会保留。
- 清理浏览器站点数据可能删除尚未正式保存的草稿。
- 草稿不会跨浏览器或跨设备同步。

### 6. 导出到系统日历

`develop` 分支支持三种 ICS 导出：

- 申请详情或日历列表中的单个事件；
- 日历页当前列表中的全部未取消事件；
- 活跃申请下的全部未来已安排事件。

操作步骤：

1. 展开对应的“导出”入口；
2. 核对事件数量、日期范围、时间、地点、链接、描述和提醒；
3. 下载 `.ics` 文件；
4. 按 Apple Calendar、Google Calendar、Outlook 或其他系统日历提供的文件导入方式尝试导入。

ICS 是单向文件快照，不是个人数据备份：系统日历中的修改不会回写到秋招进度板，重复导入是否合并由具体日历客户端决定。当前尚未完成所有主流日历客户端的人工互操作验证，实际导入表现以客户端为准。普通申请备注不会写入导出文件，但文件仍包含预览中显示的公司、岗位、时间、地点或会议链接，请勿随意公开。

### 7. 管理简历版本（功能分支）

切换到 `codex/resume-library-mvp` 后，导航栏会出现“简历”：

1. 进入“简历”，填写便于自己识别的名称；目标方向和语言可以留空。
2. 首次创建时选择 DOCX 源文件、PDF 投递文件或两者，至少需要一个文件。
3. 在外部工具中修改简历并重新导出后，回到详情页上传为新版本；旧版本会继续保留。
4. PDF 可以直接在浏览器新标签页预览，DOCX 会作为文件下载。
5. 进入岗位申请详情，在“投递简历”处选择一份带 PDF 的具体版本；只有 PDF 版本可用于投递关联。

PDF 和 DOCX 单个文件均不得超过 10 MiB。应用会检查扩展名、声明类型和基本文件内容；上传失败时不会创建空版本。归档只会收起一份简历并阻止继续添加版本，不会删除已有文件或岗位申请中的历史关联。

### 8. 归档与恢复申请

不再推进的申请可以归档并记录原因。归档后，它不会出现在默认活跃列表或今日提醒中，但申请、事件和时间线仍会保留，并可从归档筛选中恢复。

## 数据、隐私与备份

### 数据保存位置

正式数据默认保存在仓库之外：

```text
%LOCALAPPDATA%\CampusHireTracker
```

数据库位于当前数据代的 `stores\<generation-id>\app.db`，简历 PDF/DOCX 位于同一数据代的 `stores\<generation-id>\attachments`。界面只保存随机对象名和校验元数据，不会用真实简历文件名作为磁盘路径。

普通的 `git pull`、删除源码目录或重新克隆仓库不会自动删除个人数据。反过来，删除源码目录也不等于删除个人数据。

应用没有账号体系、云同步或默认遥测。当前数据库没有应用层加密；`127.0.0.1` 只限制网络监听，不等于磁盘加密或 Windows 账号隔离。不要把 `%LOCALAPPDATA%\CampusHireTracker`、数据库文件、测试报告或含个人信息的 ICS 文件提交到 GitHub。

> **公开仓库隐私提醒：** 不要提交真实简历、JD 原文、面经、联系方式、包含会议链接的 `.ics`、数据库、备份、Cookie、令牌、私钥或证书。需要临时在仓库目录内处理私密文件时，请只放入根目录下的 `private-data/`、`uploads/` 或 `exports/`；这些目录已被 `.gitignore` 忽略。提交前仍应执行 `git status` 逐项核对，不能把忽略规则当作唯一保护。

`.gitignore` 没有全局忽略 `.pdf` 或 `.docx`，以便未来可以提交不含个人信息的文档模板和测试夹具。因此，真实简历和 JD 即使采用这些格式，也必须由提交者主动放在上述私密目录或仓库之外。

### 当前阶段的人工备份

完整 ZIP 备份与受支持的恢复流程尚未实现。当前只能把下面的方法作为额外的人工保护措施，不能视为正式恢复功能：

1. 关闭运行 `start.cmd` 的窗口，确认应用已经停止；
2. 在文件资源管理器地址栏输入 `%LOCALAPPDATA%`；
3. 将整个 `CampusHireTracker` 文件夹复制到仓库之外的安全位置；
4. 使用日期命名副本，例如 `CampusHireTracker-2026-09-10`。

浏览器中尚未正式保存的备注草稿不会随该目录副本一起保存。不要在应用运行时只复制单个 `app.db` 文件；简历版本库同时依赖数据库和 `attachments` 目录，所以必须复制整个 `CampusHireTracker` 文件夹。

## 更新代码

`update.cmd` 与 `restore.cmd` 当前都是安全占位，会明确拒绝执行；它们不会自动更新、迁移或恢复数据。只有在维护者明确说明目标提交与当前 Alpha 数据兼容时，才应手动获取新代码：

1. 停止应用；
2. 按上一节复制一份个人数据目录；
3. 在仓库目录执行：

```powershell
git status
git pull --ff-only
.\setup.cmd
.\start.cmd
```

如果 `git status` 显示本地代码改动，或 `git pull --ff-only` 失败，请先停止，不要使用强制重置命令覆盖文件。

这些命令只更新源码和生产构建，不等于受支持的数据迁移流程。在 `main` 与 `develop` 之间切换时，也应停止应用并重新运行 `setup.cmd`。当前 Alpha 不承诺任意提交或任意版本之间的数据升级、降级兼容。

## 开发与测试

### 开发模式

安装依赖后，可以使用隔离的数据目录启动热更新开发服务器：

```powershell
$env:CAMPUS_HIRE_TRACKER_DATA_DIR = (Join-Path $PWD '.test-data\manual')
npm run dev
```

停止开发服务器后清除当前 PowerShell 会话中的覆盖值：

```powershell
Remove-Item Env:CAMPUS_HIRE_TRACKER_DATA_DIR
```

不要让开发测试默认连接正式的 `%LOCALAPPDATA%\CampusHireTracker` 数据。

### 提交前验证

```powershell
npm run verify
npm run db:check
```

`npm run verify` 会依次执行 ESLint、TypeScript 类型检查、Vitest 单元/集成测试和生产构建。`npm run db:check` 会在系统临时目录验证真实文件型 libSQL/Drizzle 运行能力，不读取个人数据库。

### 浏览器端到端测试

第一次执行时安装项目固定版本对应的 Chromium：

```powershell
npm run test:e2e:install
```

关闭所有占用 `127.0.0.1:3210` 的应用实例，然后运行：

```powershell
$env:CI = '1'
npm run test:e2e
Remove-Item Env:CI
```

测试使用 `.test-data/e2e` 下的隔离数据。不要在正式应用仍占用 `3210` 端口时运行端到端测试。

## 常见问题

### Node.js 版本检查失败

安装 Node.js 24 LTS，重新打开 PowerShell，再用 `node --version` 确认主版本为 24。若电脑同时安装多个 Node.js 版本，请确认当前终端实际使用的版本。

### `setup.cmd` 安装依赖失败

确认能够访问 npm 软件包源，并检查仓库中的 `package-lock.json` 没有被修改。不要从别人电脑复制 `node_modules`。

### `127.0.0.1:3210` 已被占用

先检查是否已经打开另一个 `start.cmd` 或 `npm run dev` 窗口，并关闭对应窗口。不要为了绕过错误随意修改端口；固定地址同时关系到浏览器草稿的存储身份。

### 页面打不开或缺少构建

停止当前进程，重新执行：

```powershell
.\setup.cmd
.\start.cmd
```

### 删除仓库后数据还在

这是预期行为。源码和个人数据刻意分开保存。只有在确认不再需要、并自行保留必要副本后，才应单独处理 `%LOCALAPPDATA%\CampusHireTracker`。

## 当前限制

以下能力尚未完成：

- 完整备份、恢复和自动安全更新
- 通用 JD、面经资料库及其附件；当前可以先记录在申请备注或来源链接中
- 应用内简历排版/正文编辑、模板系统和 AI 简历优化；简历功能分支只管理外部编辑后上传的 DOCX/PDF 版本
- 标签管理界面，以及事件编辑、改期和删除界面
- CSV/XLSX 导入导出
- 招聘会资料管理和从招聘会转换申请
- 完整月历视图
- PWA、系统级浏览器通知和离线正式编辑
- 可选 AI 辅助、统计分析和分享包
- 账号、公开注册、云同步、邮件服务或在线内容社区

当前正式验证目标是 Windows 桌面浏览器。手机、macOS 和 Linux 不属于本 Alpha 的支持承诺。
