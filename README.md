# 秋招进度板

> 仓库名：`campus-hire-tracker`

秋招进度板是一款本地优先的个人求职管理工具。它以“岗位申请”为主线，把进度、下一步行动、面试日程、招聘会、JD、面经和复盘放在同一套可追溯的数据模型中。

稳定基线是可运行的 **M1-A 内部 Alpha**（`main` 与 `m1-a` 标签）；当前 `develop` 开发线继续构建 M1-A.1。首个版本面向 Windows，本地运行，不依赖账号、云端服务或远程数据库。朋友可从 GitHub 仓库克隆代码，各自保存独立数据。

## 快速开始

环境要求：Windows 10/11 x64、Node.js 24、npm 11。

1. 双击 `setup.cmd` 安装固定版本的依赖、检查本地数据库并构建应用。
2. 双击 `start.cmd` 启动应用。
3. 浏览器打开 `http://127.0.0.1:3210`。

默认数据保存在 `%LOCALAPPDATA%\CampusHireTracker`，不会写入 Git 仓库。开发者也可以运行：

```powershell
npm ci
npm run dev
```

提交代码前建议运行 `npm run verify`。

### 备注草稿恢复（develop / M1-A.1）

申请详情中的备注会在输入后约 650 毫秒暂存到当前浏览器的 IndexedDB，并在正式提交前再次确保最新内容已写入。正式保存失败或发生版本冲突时，草稿不会被清除；保存成功后才会清理对应草稿。

重新打开页面发现草稿与数据库内容不同时，界面会并列展示已保存版本和每一份候选草稿，包含保存时间及版本信息，由用户逐份选择“恢复这份草稿”或“放弃这份草稿”。多个标签页各自保留独立候选，一个标签页保存时不会清除其他不同内容。IndexedDB 不可用时会显示非阻塞警告，数据库正式保存仍可尝试使用。

浏览器草稿只用于意外刷新后的临时恢复，不代表离线正式编辑、跨浏览器同步、备份或 Service Worker 支持。

### 系统日历导出（develop / M1-A.2）

日历页可以在下载前预览并导出“当前列表”或“全部未来事件”，申请详情和日历列表中的单个未取消事件也可以独立导出。当前日历页没有筛选条件，因此“当前列表”准确指活跃申请下的全部未取消事件，包含过去和未来；“全部未来事件”只包含从导出时刻起仍有效的已安排事件。已完成事件可以进入当前列表快照，但不会带提醒。

导出的 `.ics` 文件使用事件的稳定 UID，支持定时与全天事件，并包含标题、时间、地点、会议链接、非敏感描述和默认提醒。普通备注不会写入日历文件。下载时会重新读取数据库并核对预览快照；若期间内容变化，会要求刷新后重新确认，而不会静默导出未预览的新内容。该能力是单向文件导出：系统日历中的修改不会回写到秋招进度板，重复导入是否合并仍由具体日历客户端决定。

## 产品原则

- 打开首页就能回答：“我现在最需要做什么？”
- 活跃申请必须处于三种可解释状态之一：有明确下一步、带复查日期的等待状态，或显式标记为需要补充下一步并进入风险队列。
- 人是进度状态的最终确认者；系统只提醒，不擅自推进流程。
- 用户数据、附件、备份、日志和密钥绝不进入 Git 仓库。
- AI 是可选录入助手，不是核心功能的运行前提。
- 先保证数据可恢复，再追求功能丰富。

## 版本范围

M1-A 已实现：

- 申请新增、编辑、阶段推进、归档与恢复
- “有下一步 / 等待中 / 待补下一步”三种注意力状态
- 面试、笔试、截止日期和等待复查等事件记录
- 今日行动首页、申请列表、事件日历列表与时间线
- 重复申请警告、时间冲突警告和并发修改保护
- 本地 SQLite/libSQL 数据库、固定回环地址与基础安全响应头

develop 当前新增（尚未纳入 M1-A 稳定标签）：

- 可恢复浏览器临时草稿的申请备注编辑
- 带完整预览与隐私边界说明的 ICS 系统日历单向导出

仍待后续里程碑实现：完整 ZIP 备份/恢复与安全更新、附件与资料库、表格导入导出、完整月历、PWA、浏览器通知、可选 AI 和统计。当前 `update.cmd` 与 `restore.cmd` 会明确拒绝执行，不会进行不完整或破坏性操作。

明确不在本地版本范围内：账号体系、公开注册、云同步、服务端邮件、在线内容社区、招聘网站插件和默认遥测。

## 技术栈

- Next.js 16、React 19、TypeScript、Node.js 24 LTS
- Drizzle ORM 稳定版、SQLite/libSQL
- Vitest、Playwright
- Windows 双击脚本：`setup.cmd`、`start.cmd`；更新和恢复入口当前为安全占位

依赖版本已通过 lockfile 固定。
