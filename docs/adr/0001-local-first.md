# ADR-0001：采用本地优先、单机运行架构

- 状态：已接受
- 日期：2026-09-08
- 决策者：产品所有者与开发者
- 关联：[ADR-0002](0002-user-data-outside-repo.md)、[ADR-0003](0003-web-stack.md)、[ADR-0004](0004-backup-format-and-encryption.md)

## 背景

秋招进度板首先服务产品所有者本人，之后通过 GitHub 私有仓库邀请 3–5 位朋友各自克隆体验。当前目标是零预算验证“申请进度清楚、日程零遗漏、下一步明确”这一核心价值，而不是经营一个在线服务。

求职记录、JD、面经、面试官信息和附件都可能包含敏感数据。若首版引入远程账号、云数据库、邮件后台和同步冲突处理，会显著扩大开发、运维和隐私边界，却不会直接验证核心工作流。

## 决策

首版采用**本地优先、每台电脑一个独立工作区**的架构：

1. 应用作为 Windows 上的本地 Node.js 服务运行，并且只使用固定 origin `http://127.0.0.1:3210`；浏览器通过该 IPv4 loopback 地址访问。端口被非本应用进程占用时明确失败，不静默切换 origin。
2. 业务数据保存在本机 SQLite/libSQL 文件中，附件保存在本机受控目录中；正常使用不依赖互联网。
3. GitHub 仓库只分发代码、数据库迁移、脚本和文档。每位体验者拥有互不连接、互不共享的数据副本。
4. 首版不实现账号体系、公开注册、云同步、服务端邮件、在线分享和默认遥测。
5. 系统日历 ICS 是应用关闭后的主要可靠提醒渠道；站内和浏览器通知属于增强能力。
6. PWA 只承诺在运行本地服务的同一台 Windows 电脑和上述固定 origin 上提供安装外观、应用壳缓存和 IndexedDB 离线草稿。它不把本地 Node 服务变成可离线后端，也不承诺手机通过局域网访问。
7. 可选 AI 仅在用户主动配置接口并明确触发时联网；没有 API Key 时，规则提取和所有核心功能仍可使用。
8. 若未来增加多用户、远程访问或云同步，应新建 ADR 并重新设计身份、授权、数据隔离、同步和运维，而不能把它当作一个配置开关。

## 理由

- 最短路径覆盖真实秋招场景，降低首次可用版本的交付风险。
- 数据默认不离开用户设备，隐私边界清晰。
- 无需域名、备案、服务器和持续运维成本。
- 单机 SQLite 与个人规模的数据量和写入并发相匹配。
- 仍保留 Web UI 的响应式开发效率，并通过结构化备份支持未来迁移。

## 后果

### 正面

- 克隆、初始化后即可使用，朋友之间不存在账号或租户数据串扰。
- 应用即使断网也能完成核心读写、附件查看和导出。
- 数据和附件可以通过版本化备份整体迁移，而不依赖某家云服务。
- 系统只需要维护一个本地进程和一个本地数据库，故障面较小。

### 代价与限制

- 电脑关闭或本地服务停止后，应用不能主动执行浏览器通知或发送邮件；重要提醒必须导出到系统日历。
- 不提供跨设备实时同步；在两台电脑分别录入会产生两个独立事实来源。
- 手机通过 `http://<局域网地址>` 访问不在支持范围内。Service Worker 要求安全上下文；本项目只依赖浏览器对 `127.0.0.1` loopback origin 的本机安全上下文待遇，不接受 `localhost` 别名或局域网地址。
- 朋友更新代码时各自承担本机运行环境差异，因此必须维护可重复的初始化、更新、迁移和恢复流程。
- “本地”不等于“自动加密”。首版依赖 Windows 用户账户和磁盘保护；共享电脑或高威胁模型需要另行评估应用级加密。

## 被否决的方案

### 立即部署免费云服务

否决原因：会提前引入账号、授权、隐私声明、远程备份、邮件和免费额度不确定性，偏离当前验证目标。

### 纯静态站点或 GitHub Pages

否决原因：静态浏览器应用无法直接使用 Node 文件系统和本机 SQLite；将全部数据放入浏览器存储会弱化附件管理、备份恢复和版本化迁移能力。

### Electron 或 Tauri 桌面应用

否决原因：首版不需要额外的桌面打包、签名和更新链路。若以后需要托盘后台、原生通知或完全无 Node 安装体验，再单独评估。

### 局域网共享一台主机

否决原因：会暴露网络监听、主机防火墙、并发访问和身份授权问题，也无法保证 PWA/通知所需的安全上下文。

## 验证标准

- 在联网被禁用时，除可选 AI、打开外部链接和 Git 更新外，核心流程仍可完成。
- `start.cmd` 启动后的 origin 只能是 `http://127.0.0.1:3210`，不得监听 IPv6、`localhost` 别名、`0.0.0.0` 或局域网网卡，也不得因端口占用自动漂移。
- 一台新 Windows 机器可完成“克隆 → 初始化 → 启动 → 创建数据 → 备份 → 恢复”。
- 两个独立克隆不会读写仓库目录中的运行时数据，也不会共享个人数据。
