# 实施计划

## 1. 目的与执行规则

本计划把已确认的产品范围拆成三个始终可运行、可验证、可回退的里程碑。每个任务必须关联本文的工作包、产品验收标准或缺陷；不能以“顺手做”为理由扩展账号、云同步、服务端邮件、公开社区等非首版能力。

执行时遵循以下规则：

- 先完成数据安全和可恢复性，再扩大功能面。
- 每次只合并可启动、可迁移且测试通过的状态；主分支不得长期处于半成品状态。
- 领域规则写在服务层并由数据库约束兜底，不能只靠界面校验。
- 所有持久化改动必须包含迁移、旧数据样例、失败路径和恢复说明。
- 所有用户文件必须位于 `%LOCALAPPDATA%\CampusHireTracker`，仓库内只允许匿名测试夹具。
- 新依赖必须说明用途、许可证、维护状态和替代方案，并锁定在 lockfile 中。

## 2. 依赖关系与交付顺序

```text
工程基线
  ├─ 数据目录与单实例锁
  ├─ 数据库、迁移与领域约束
  ├─ 本地 HTTP 安全边界
  └─ 测试夹具与自动化骨架
          │
          ▼
里程碑 1：核心求职循环
  申请/阶段 ─→ 行动模式 ─→ 事件 ─→ 今日/看板/表格
       │                         └────→ 基础 ICS 导出
       └─────────────────────────────→ 时间线
          │                              │
          └──────────────→ 备份 v1 ─────┘
                          │
                          ▼
里程碑 2：资料与数据安全
  资料模型 ─→ 附件 ─→ 搜索
  招聘会 ────────────→ 申请关联
  导入预览 ─→ 事务导入 ─→ 导出/完整恢复
  回收站 ────────────→ 自动备份与保留策略
                          │
                          ▼
里程碑 3：增强体验
  PWA/草稿 ─→ 浏览器通知
  规则提取 ─→ 可选 AI 草稿
  资料选择 ─→ 脱敏分享
  领域查询 ─→ 基础统计
```

横向依赖：安全基线、可访问性、中文文案、响应式布局、错误处理和测试门禁贯穿三个里程碑。里程碑 2 依赖里程碑 1 的实体 ID 与时间线稳定；里程碑 3 不得通过修改核心状态机来实现增强功能。

## 3. 全局完成定义

任一工作包只有同时满足下列条件才算完成：

- 行为与 PRD、术语表、数据模型及 UX 规格一致，异常和空状态有明确行为。
- TypeScript 类型检查、静态检查、单元测试和相关集成测试通过。
- 用户可见主流程至少有一条 Playwright 成功路径；高风险功能另有失败路径。
- 新增数据结构有前向迁移；迁移可重复执行或能安全识别已执行状态。
- 错误不会把 JD、面经、附件内容、API Key、完整路径或导入原文写入日志。
- 键盘可操作，状态不只依赖颜色，明暗主题下文字与焦点可辨认。
- 数据变更成功后才显示成功反馈；失败时不留下部分写入。
- 文档、示例、脚本和界面术语同步更新。
- 在支持的 Windows 环境通过对应里程碑的全新克隆验证。

### 3.1 缺陷严重度与发布门禁

需求优先级 `P0/P1` 只表示功能优先级，不作为缺陷等级。缺陷统一使用：

- `S0`：数据丢失、安全问题或应用不可启动；
- `S1`：核心流程不可用且没有可接受绕路；
- `S2`：功能受损但存在可接受绕路；
- `S3`：外观或轻微体验问题。

任何可供自己或朋友使用的发布版本都必须满足 `S0 = 0` 且 `S1 = 0`；S2/S3 必须记录影响与处理计划，但不与需求 P0/P1 混称。

## 4. 工程基线

工程基线不是第四个里程碑，而是里程碑 1 的前置门禁。

### F01：项目与质量工具

交付：Next.js 16、React 19、TypeScript、Node.js 24 LTS 项目；固定依赖的 lockfile；Vitest 与 Playwright；统一的 `typecheck`、`lint`、`test`、`test:e2e`、`build` 脚本。

完成定义：

- `npm ci` 能在没有全局项目依赖的环境完成安装。
- 最小页面在生产模式固定监听 `127.0.0.1:3210`，不得监听 IPv6、`localhost` 别名、`0.0.0.0` 或在占用时改用其他端口。
- CI 在干净检出上运行类型检查、静态检查、单元/集成测试和生产构建。
- 依赖审计结果被记录；严重漏洞必须解决或形成带期限的风险接受记录。

### F02：外部用户数据目录

交付：统一路径解析模块、目录初始化、权限检查、磁盘空间错误处理和单实例锁。目录契约见 `LOCAL_OPERATIONS.md`。

完成定义：

- 数据库、附件、备份、草稿和日志均不落入仓库。
- 路径只由可信根目录与内部生成的对象键拼接；业务字段不能直接成为文件路径。
- 第二个进程启动时给出可操作提示，不并发写同一数据库。
- 初始化可重复执行，不覆盖现有数据。

### F03：数据库、迁移与事务边界

交付：SQLite/libSQL 连接、Drizzle schema、迁移表、事务封装、外键启用、测试数据库工厂。

完成定义：

- 数据库启动时检查 schema 版本，不支持的新版本必须拒绝启动且不写入。
- 迁移前能触发快照；迁移失败不标记成功，并能按恢复演练回到旧版本。
- 外键、唯一性、检查约束和软删除过滤有集成测试。
- 测试使用独立临时目录，不接触真实 `%LOCALAPPDATA%` 数据。

### F04：本地 Web 安全基线

交付：Host/Origin 校验、CSRF 防护、HTML 净化、统一输入验证、响应安全头、敏感日志脱敏和健康检查端点。

完成定义：

- 非回环 Host、意外 Origin 和跨站写请求被拒绝。
- 用户富文本、导入内容和链接标题不能执行脚本。
- 健康检查不返回数据内容、目录、环境变量或凭据。
- 安全回归用例纳入自动化测试。

## 5. 里程碑 1：核心求职循环

目标：用户能可靠回答“现在最需要做什么”，并完成从建档、推进、安排事件到追溯历史的闭环。

### M1-00：首次引导与示例数据

依赖：F01–F04、M1-01、M1-04。编号表示产品入口，不表示必须最先完成；应在申请与事件能力可用后收口。

范围：最多三步且可跳过的首次引导、本机存储说明、开始方式选择、提醒边界说明，以及显式加载/删除的示例数据。

完成定义：

- 首次进入可创建第一条申请、加载示例或直接进入空态；M2 前的导入入口明确标注尚不可用，不形成死路。
- 不在首次打开时索取浏览器通知权限，不强迫配置 AI 或导入数据。
- 示例数据全程带标记，统计和正式导出默认排除；“删除全部示例”不影响真实数据。
- 跳过或重复进入引导不会重置设置、数据库或已有记录。

### M1-01：公司与岗位申请

依赖：F02、F03。

范围：公司、申请、批次、来源、来源链接、地点、优先级、标签、备注；全局快速新建仅要求公司和岗位；阶段默认“机会池”，优先级默认“中”，来源默认“未填写”而非“自定义”。M1 来源控件隐藏“招聘会”，直到 M2-04 提供可关联的招聘会实体。从 M1 起，应用备注等长文本以固定 origin IndexedDB 的 `EditorRecoveryDraft` 保护尚未成功保存的内容。

完成定义：

- 可创建、查看、编辑和筛选申请；公司名称规范化但保留用户显示文本。
- 相同“公司 + 岗位 + 批次”创建时警告但允许继续，用户取消时不写入。
- 所有写操作具备失败反馈和重复提交保护。
- `EditorRecoveryDraft` 只覆盖长文本未保存内容；不同编辑器实例使用独立候选，删除核对修订号，保存成功只清理与正式内容相同的候选。恢复时逐份比较版本，不进入正式备份。M1 不注册 Service Worker，也不提供离线正式编辑。
- 示例数据可由用户删除，绝不混入真实统计或导出。

### M1-02：阶段、归档与时间线

依赖：M1-01。

范围：固定主阶段；拖动或详情编辑阶段；归档原因；不可变事实型时间线；撤销最近一次看板拖动。

完成定义：

- 只有用户动作能改变主阶段；事件结束不得自动推进。
- 每次阶段变化在同一事务写入时间线，包含旧值、新值和发生时间。
- 拖动后可撤销，撤销本身可追溯；刷新页面后状态一致。
- 归档项默认退出活跃视图，但可筛选和恢复。
- 归档不取消既有事件；相关事件保留为历史事实，但默认退出今日与提醒查询，恢复后未来有效事件重新参与查询。
- 恢复时可选择任一非归档阶段，`archived_from_stage` 只作为默认建议；恢复流程要求设置行动、等待或明确接受待补。

### M1-03：行动模式

依赖：M1-01、M1-02。

范围：每条活跃申请只能处于一个行动模式：有一个下一步行动、等待中且有复查日期，或明确标记为“缺少下一步”的待补状态。`waiting_for` 等待对象可选；等待模式只要求 `waiting_review_event_id` 必填，由该复查事件承载日期/时刻。待补合法来源为快速创建、不完整导入/迁移、完成或移除行动/等待后用户明确选择稍后补充，以及归档恢复时明确接受待补。

完成定义：

- 下一步与等待不能同时有效；待补必须进入“缺少下一步”修复队列而非被默认行动掩盖。
- 下一步完成、替换或转为等待都写入时间线。
- 移除行动或等待不得静默制造待补；必须先记录用户“稍后补充”的明确选择。
- 复查日期到期后出现在今日首页；时区边界有测试。
- Offer 可继续保留下一步；归档后不要求下一步。

### M1-04：事件与冲突检测

依赖：M1-01。

范围：直接关联申请的面试、测评/笔试、投递截止、跟进/复查等事件；时间、时区、地点/链接、提醒设置；冲突警告但不阻止保存；基础 ICS 单向导出与预览。招聘会及其事件在 M2-04 引入。

完成定义：

- 支持定时和全天事件；结束不得早于开始。
- 定时事件开始必填、结束可选；不填结束时按时间点保存，界面和服务层不得补默认时长。
- 区间与时间点的冲突规则以数据模型为唯一实现依据；保存前展示命中的冲突对象，用户确认后仍可保存。
- 修改或删除事件不会改变申请阶段。
- M1 面试事件不依赖面试轮次；M2 引入轮次后可以由用户显式归入轮次，不自动复制或猜测。
- 跨午夜、夏令时样例和 Asia/Shanghai 默认时区均有测试。
- ICS 对同一事件使用稳定 UID，正确导出定时/全天事件和提醒；默认排除私人备注等敏感内容。

### M1-05：今日、看板、表格与基础日历

依赖：M1-02、M1-03、M1-04。

范围：今日首页按“逾期/冲突、今天、未来 7 天、等待复查、缺少下一步”排序；申请看板/表格切换；桌面月历与日程列表；移动窄屏以列表为主。

完成定义：

- 同一对象不会因属于多个分组而产生含义不明的重复；必要重复有来源标识。
- 筛选、排序和视图切换后刷新行为符合 UX 规格。
- 看板支持键盘替代操作，不以拖动作为唯一推进方式。
- 空状态提供“新建申请”或“导入”入口。

### M1-06：完整备份 v1 和本地脚本

依赖：F01–F03、M1-00–M1-04。

范围：直接实现 `IMPORT_EXPORT_SPEC.md` 的完整备份 v1、`setup.cmd`、`start.cmd`、`update.cmd`、`restore.cmd` 初版和健康检查；不得另造临时格式，也不得把直接复制活动数据库当作正式备份。尚未启用的 M2/M3 表按 v1 契约输出空数组。

完成定义：

- 用户能双击完成首次初始化与日常启动，无需管理员权限。
- 更新在迁移前创建并校验备份；候选迁移失败时活动 release-generation 对从未改变，指针切换后启动失败时由 helper 原子切回并验证完整 previous 对，同时保留脱敏诊断摘要。备份只作为最后恢复手段，不用于覆盖本来完好的活动数据库。
- v1 备份的 manifest、JSON、ZIP 与校验信息符合协议；尚未启用表的空数组通过 schema 校验。
- `restore.cmd` 在服务停止状态完成预检、恢复和一致性核对，可在测试目录恢复为等价数据。
- 完成一次“全新 clone → setup → start → 写入样例 → update 演练 → 恢复”验证。

### 里程碑 1 出口条件

- 所有 M1 工作包达到完成定义，需求 P0 验收项全部通过，且缺陷 `S0 = 0`、`S1 = 0`。
- 连续运行核心 E2E 3 次无偶发失败。
- 人工完成一次真实申请的建档、等待、事件、阶段推进、归档与恢复。
- 关闭并重启应用后，所有状态、排序和时间线一致。
- 已生成可恢复备份，且恢复演练成功。
- 将关键事件导入系统日历后，时间、提醒和稳定 UID 正确；应用关闭后的提醒依赖系统日历。

## 6. 里程碑 2：资料与数据安全

目标：把 JD、面经、招聘会和附件纳入可信数据体系，并让导入、导出、删除与恢复可控。

### M2-01：资料库与富文本

依赖：M1-01、F04。

范围：JD 快照、外部资料、个人面试记录；与公司、申请和面试轮次的关联；富文本编辑、自动保存和 Markdown 导出。个人面试记录入口在 M2-02 的轮次可用后启用，并必须关联轮次。富文本沿用 M1 的 `EditorRecoveryDraft`，不创建另一类编辑器草稿。

完成定义：

- 三类资料在界面和数据模型中明确分离。
- JD 快照正文必填；外部资料标题必填且来源 URL/正文至少一项；个人面试记录正文必填并关联具体轮次。一般 JD/外部资料仍可只关联公司或申请。
- 自动保存展示“保存中/已保存/失败”，失败草稿可恢复。
- 粘贴 HTML 经净化；搜索索引只含允许索引的纯文本。
- 个人面试记录默认不进入分享导出。

### M2-02：面试轮次

依赖：M1-01、M1-04。实施时先完成轮次实体，再启用 M2-01 的个人面试记录入口，避免形成循环依赖。

范围：自由命名的轮次、类型、顺序、时间/关联事件、面试官、结果和复盘。

完成定义：

- 可重复、重排和取消轮次；轮次结果不自动改变主阶段。
- 可把 M1 的申请级面试事件显式归入轮次；不强制迁移，也不自动生成重复事件。
- 取消轮次默认保留关联事件，并提示可选“同时取消事件”；默认选项不能改变事件状态。
- 软删除轮次时，默认在同一事务把唯一 `INTERVIEW` 事件改为直接关联所属申请，保留提醒、稳定标识和历史；用户可显式选择让事件与轮次一同进入回收站。
- 删除关联事件时轮次保留并提示缺失日程；上述反向操作规则有事务与 E2E 覆盖。
- 面试官信息按敏感数据处理，不写日志和默认分享。

### M2-03：附件

依赖：F02、F04、M2-01。

范围：图片与 PDF 的复制入库、元数据、预览、校验、孤儿清理和备份关联。附件只能直接归属于 `Material`；面试轮次附件必须通过该轮次的 `INTERVIEW_NOTE` 间接关联。

完成定义：

- 不引用原路径；以应用生成的不可猜测对象键保存。
- 扩展名、MIME 与文件签名不一致时拒绝；大小和数量受限。
- 上传失败不会留下数据库记录；文件落地后数据库登记失败只会留下可由安全等待期清理的内部孤儿对象，不会留下指向缺失文件的正式记录。
- schema 与服务层均不提供轮次到附件的直接关系；轮次快捷上传先创建或选择对应 `INTERVIEW_NOTE`。
- 路径遍历、符号链接、恶意 SVG/伪装文件和超大文件有负向测试。

### M2-04：招聘会

依赖：M1-01、M1-04。

范围：即将参加/已参加、时间地点/链接、参会公司、目标岗位、现场笔记、会后行动，以及从目标创建申请。目标现场状态固定为 `NOT_CONTACTED`“未接触”、`CONTACTED`“已接触”、`FOLLOW_UP_NEEDED`“需跟进”、`NOT_INTERESTED`“不再考虑”。

完成定义：

- 一场招聘会可关联多家公司和申请，删除关联不级联删除申请。
- 从目标创建申请沿用重复警告规则。
- 招聘会事件与详情时间一致，冲突变更有明确确认。

### M2-05：全局搜索与筛选

依赖：M1-05、M2-01–M2-04。

范围：公司、岗位、JD、面经和招聘会；阶段、优先级、来源、标签和日期筛选。

完成定义：

- 中文文本、空白、大小写和特殊字符有固定匹配规则。
- 回收站内容默认不出现在搜索结果。
- 结果显示关联上下文，不能泄露已删除或不可分享片段。

### M2-06：表格导入与数据导出

依赖：M1-01–M1-04、M2-04；遵循 `IMPORT_EXPORT_SPEC.md`。

范围：CSV/XLSX 预览、列映射、错误和重复项、事务导入、会话内撤销；仅实现 CSV 导出，不实现 XLSX 导出。

完成定义：

- 文件选择和预览不写正式数据；确认后单事务提交，失败整体回滚。
- 歧义日期必须由用户确认；未知枚举不得静默映射。
- `next_action` 与 `review_at` 同时存在的行必须在预览中阻塞；仅行动映射为可行动、仅复查映射为等待、两者都空映射为显式待补。
- 导出防电子表格公式注入；导入内容不得进入日志。
- UI、测试和发布说明不得因支持 XLSX 导入而声称支持 XLSX 导出。
- 标准样例、脏数据、重复数据、超限文件和回滚路径测试通过。

### M2-07：回收站、自动备份与完整恢复

依赖：M2-01–M2-06。

范围：30 天回收站、永久删除二次确认；在 M1 备份 v1 上开始写入资料/附件/招聘会等已启用数组，并增加附件打包、每日轮换、可选强加密、校验，以及通过新 generation 与单一活动指针完成的一致恢复。

完成定义：

- 普通删除只软删除；到期清理可审计但不记录内容。
- 同名或重复冲突的恢复必须让用户选择合并到现有记录或使用建议后缀重命名；不得静默处理，两条路径都不能被名称冲突永久阻断。
- 自动备份不会覆盖最后一份已知可用备份；磁盘不足时明确告警。
- 恢复先校验、再构建候选 generation，服务停止后仅原子替换单一活动指针；持久化 journal 确保任一步中断都能继续验证或回到原 generation。
- 设置页单独列出旧 generation 与备份；清理旧 generation 前说明其中可能含历史数据且会失去对应快速回退，未被 active/journal 引用时才允许整代删除。
- 当前格式及上一主版本样例恢复通过；损坏、路径穿越和压缩炸弹样例被拒绝。

### 里程碑 2 出口条件

- 使用包含中文 JD、图片、PDF、面试轮次和招聘会的样例完成备份/清空测试环境/恢复，关联与校验值一致。
- 完成 CSV/XLSX 预览、导入与撤销验证，以及 CSV 导出往返验证；确认不存在 XLSX 导出入口或测试承诺。
- 回收站保留、恢复和永久删除路径均通过测试。
- 安全负向测试无高危失败，自动备份连续运行测试符合保留策略。

## 7. 里程碑 3：增强体验

目标：在不改变本地优先和人工确认原则的前提下，提高录入、提醒、分享和复盘效率。

### M3-01：PWA、离线壳与草稿

依赖：M1-05、M2-01。

范围：固定 `http://127.0.0.1:3210` origin 上的可安装清单、应用壳缓存、最近数据只读展示，以及 `OfflineCaptureDraft` 断连快速创建与联网后确认写入。该对象不同于 M1 长文本 `EditorRecoveryDraft` 和 SQLite `CaptureDraft`。

完成定义：

- 不声称完整离线编辑；离线界面明确标识数据新鲜度和限制。
- `OfflineCaptureDraft` 写入必须去重并要求确认，不静默覆盖正式记录，也不得覆盖或冒充 `EditorRecoveryDraft`。
- Service Worker 升级失败不会让应用永久白屏，提供清缓存恢复指引。
- 端口被非本应用进程占用时明确失败，不静默换 origin；IndexedDB 草稿可查看和清空，并明确不进入完整备份。

### M3-02：浏览器通知

依赖：M1-04、M3-01。

范围：用户主动授权后的浏览器通知，用作应用运行期间的便利提醒；M1 已提供关闭应用后使用的系统日历导出。

完成定义：

- 拒绝通知权限不影响任何核心功能，也不重复骚扰。
- 明确说明应用关闭时浏览器通知不可靠，系统日历是关闭应用后的主要提醒。

### M3-03：规则提取与可选 AI

依赖：M1-01、M1-04、M2-01、F04。

范围：对用户粘贴的正文或链接文本做规则提取；兼容接口地址、模型名和 API Key；AI 只生成 SQLite `CaptureDraft` 待确认草稿。URL 只作为来源保存，首版不自动下载远程网页正文。

完成定义：

- 未配置 Key 时规则提取可用，AI 控件隐藏或明确为可选。
- API Key 只在 Windows 凭据管理器；不进入数据库、配置、日志、备份或 Git。
- 发送前列出将发送的字段；用户取消时不发起网络请求。
- AI 输出经过不可信输入处理，必须预览确认后才写正式数据。

### M3-04：脱敏分享

依赖：M2-01–M2-03、F04。

范围：字段选择、敏感项提示、预览确认、自包含 HTML/Markdown；PDF 由浏览器打印。

完成定义：

- 默认不选私人备注、联系方式、面试官、申请进度和本地路径。
- 导出文件不含脚本、追踪资源、API Key、内部 ID 或附件绝对路径。
- 分享文件在断网环境可打开，删除源数据不影响已导出文件的风险有明确提示。

### M3-05：基础统计与主题

依赖：M1、M2 的稳定查询。

范围：漏斗、阶段数量、渠道结果、时间趋势；明暗主题；简体中文界面并预留国际化键。

完成定义：

- 指标口径可查看，归档和重复申请是否计入必须明确。
- 数据为空或样本很小时不生成误导性成功率结论。
- 图表提供文字/表格等价信息，颜色不是唯一编码。

### 里程碑 3 出口条件

- 在 Windows 支持浏览器验证安装、升级、离线草稿和通知拒绝路径。
- 有 Key/无 Key、接口失败、超时和恶意输出的 AI 路径均不影响核心数据。
- 脱敏分享通过字段泄漏检查；统计口径通过固定数据集验证。

## 8. 发布候选与 GitHub 分发门禁

每个可供朋友体验的版本必须：

1. 从带签名或受保护的版本标签构建，版本号、schema 版本和备份格式版本可查询。
2. 在干净 Windows 环境完成 `clone → setup.cmd → start.cmd` 验证。
3. 从上一发布版真实升级样例运行 `update.cmd`，验证成功和故意失败回滚。
4. 完成一次完整备份恢复，并核对记录数、关联数和附件 SHA-256。
5. 确认仓库、构建产物和日志中没有真实数据、`.env`、API Key、数据库或附件。
6. 确认缺陷 `S0 = 0`、`S1 = 0`，并记录尚未关闭的 S2/S3。
7. 发布说明列出数据迁移、已知限制、备份提醒和回退办法。

## 9. 风险清单

| 风险 | 触发信号 | 预防/缓解 | 发布阻断条件 |
| --- | --- | --- | --- |
| SQLite 迁移损坏数据 | 迁移中断、schema 不一致 | 迁移前快照、临时副本验证、版本检查 | 无成功恢复演练 |
| Git 更新破坏本地环境 | 脏工作区、依赖或构建失败 | 拒绝脏树、只允许快进、更新前验证与备份 | 不能回到旧提交和旧数据 |
| 附件与数据库失配 | 孤儿文件、缺失对象 | 两阶段写入、校验任务、完整备份 | 恢复后有关联附件缺失 |
| 本地服务暴露到局域网 | 监听 `0.0.0.0`、异常 Host | 强制回环绑定、Host/Origin 校验 | 其他设备可直接访问数据 |
| 富文本/导入造成 XSS | `<script>`、事件属性执行 | 服务端校验、净化、CSP、测试语料 | 任意存储型脚本可执行 |
| ZIP/附件路径遍历 | `..`、绝对路径、符号链接 | 内部对象键、规范化后根路径检查、拒绝链接 | 可写出受控目录 |
| 备份不可用或磁盘写满 | 校验失败、剩余空间不足 | 写临时文件、校验后原子改名、轮换与告警 | 无至少一份已知可用备份 |
| API Key 泄漏 | 日志/导出出现凭据 | Windows 凭据管理器、集中脱敏、泄漏测试 | 任一产物包含测试秘钥模式 |
| 时间/时区错误导致遗漏 | 跨午夜显示错误、ICS 偏移 | UTC 持久化 + IANA 时区、边界测试 | 关键事件显示或导出错误 |
| 范围膨胀拖延核心验证 | 同期开发账号/社区/插件 | 工作包门禁、非目标清单、变更需 ADR | M1 尚未闭环却引入服务端依赖 |
| PWA 缓存旧版本 | 升级后白屏或 schema 不匹配 | 版本化缓存、更新提示、恢复入口 | 无法无损退出坏缓存 |
| AI 内容越权写入 | 未确认即改变数据 | 明确发送预览、草稿隔离、人工确认 | AI 可直接改阶段或正式资料 |

## 10. 建议的 Issue 与合并粒度

- 一个 Issue 对应一个工作包中的单一可演示结果，预计不超过数个工作日。
- 数据库迁移、领域服务、界面和测试可拆分为依赖明确的子 Issue，但同一迁移必须与最低兼容代码同版本发布。
- PR 描述必须填写：关联工作包、用户可见变化、数据影响、测试证据、回退方式、安全/隐私检查。
- 大型 PR 不得同时修改状态机、备份格式和更新脚本；这些高风险面应独立评审。
- 发现需求冲突时先更新对应事实来源和 ADR，再改实现，不在代码评论里形成隐性产品规则。
