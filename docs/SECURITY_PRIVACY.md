# 安全与隐私

## 1. 安全目标与边界

秋招进度板处理求职进度、公司联系、面试安排、面经、附件和可选 AI 凭据。首版本地运行，安全目标是：默认只让当前 Windows 用户访问；不因 Web 服务、附件、导入、备份、日志或 Git 分发造成额外泄露；任一输入失败时优先保住原数据。

本地优先不等于天然安全。应用仍包含浏览器、本地 Node 进程、SQLite、文件系统、第三方依赖和可选外部 AI 服务等信任边界。

明确假设：

- Windows 账户本身可信，设备未被已获得同账户权限的恶意软件控制。
- 首版数据库不做应用级加密，依赖 Windows 登录、文件权限和用户可选的设备加密。
- 应用默认只在本机使用，不提供局域网访问、远程管理、账号或云同步。
- 浏览器通知在应用关闭后不承诺可靠；系统日历承担关闭应用后的提醒。

若设备多人共用，应为每人使用独立 Windows 账户，并启用设备加密或 BitLocker。无法接受上述假设的用户不应在首版保存高度敏感资料。

## 2. 数据分类与默认处理

| 等级 | 示例 | 默认存储 | 可进入普通日志 | 可进入备份 | 可发送给 AI/分享 |
| --- | --- | --- | --- | --- | --- |
| S3 高敏感 | API Key、备份密码 | Key 仅在 Windows 凭据管理器；密码仅在本次操作内存 | 禁止 | 禁止 | 禁止 |
| S2 敏感 | 私人面试记录、面试官/联系人、会议链接、申请进度、个人备注、附件 | 本地数据库或附件目录 | 禁止原文 | 是，备份需醒目提示且可加密 | 默认禁止；逐项选择并确认后才允许发送特定内容 |
| S1 受限 | JD、公司/岗位、公开面经链接、招聘会信息 | 本地数据库 | 只允许内部 ID、类型和计数 | 是 | 仅用户选择后允许 |
| S0 公共 | 应用版本、schema 版本、公开帮助文案 | 应用或配置 | 允许 | 可选 | 允许 |

分类按最高敏感项继承：含会议链接的普通事件按 S2；含个人批注的 JD 资料按 S2；错误对象若携带原始输入也按对应级别处理。

## 3. 数据流与信任边界

```text
当前 Windows 用户
  │
  ▼
受支持浏览器 ──HTTP on 127.0.0.1:3210── 本地 Next.js 进程
                                     ├─ SQLite 数据库
                                     ├─ 附件/正式草稿/备份/日志目录
                                     ├─ Windows 凭据管理器（仅 API Key）
                                     └─ 用户明确触发时 ──HTTPS── 可选 AI 接口

固定 origin IndexedDB ── EditorRecoveryDraft / OfflineCaptureDraft（不进备份）

用户选择的 CSV/XLSX/ZIP/图片/PDF ──不可信输入──┘
GitHub 仓库与 npm 依赖 ──供应链输入───────────┘
```

浏览器发来的内容、导入文件、附件、备份包、富文本、URL、AI 响应和 GitHub Issue 内容一律视为不可信。即使文件由用户本人创建，也必须执行同样校验。

草稿有三个严格不同的边界：SQLite `capture_drafts` 中的 `CaptureDraft` 是经过服务端校验的正式本地采集草稿，位于当前 generation 并进入完整备份；M1 `EditorRecoveryDraft` 只是在固定 origin IndexedDB 中保存的长文本编辑器崩溃恢复快照；M3 `OfflineCaptureDraft` 是断连快速创建、等待用户确认的 IndexedDB 草稿。后两者都不是正式事实、不进入完整备份、不随 generation 恢复，也不能与 SQLite 行共享 ID 或双写。Service Worker 不得缓存正式资料响应，代码、界面和日志也不得把三者混称为同一种草稿。

## 4. 威胁模型

| 威胁 | 典型路径 | 影响 | 必须控制 |
| --- | --- | --- | --- |
| 局域网未授权访问 | 服务监听 `0.0.0.0` 或接受任意 Host | 全量求职数据泄露 | 强制回环绑定、Host/Origin 检查、启动时自检 |
| 跨站请求伪造 | 恶意网页向 localhost 发写请求 | 静默修改或导出数据 | SameSite cookie（如使用）、CSRF token、自定义请求头、Origin 校验 |
| 存储型 XSS | JD、面经、导入单元格或 AI 输出带脚本 | 读取并外传本地数据 | 输入校验、富文本净化、输出编码、严格 CSP |
| 路径遍历/任意文件写 | 文件名、对象键或 ZIP 成员含 `..`/绝对路径 | 覆盖用户文件或执行代码 | 内部对象键、规范化根路径检查、拒绝链接与特殊文件 |
| 恶意附件 | 伪装 MIME、SVG 脚本、畸形 PDF | 浏览器执行、解析器漏洞、资源耗尽 | 类型白名单、签名校验、大小限制、隔离响应头、禁止 SVG |
| 恶意备份/压缩炸弹 | 极高解压比、重复成员、超大数量 | 磁盘耗尽、路径逃逸 | 解压前预算、成员/总量上限、流式校验、临时目录 |
| SSRF/意外外发 | 自动抓取 URL、恶意 AI base URL、DNS rebinding 或重定向 | 访问本机/云元数据服务或发送敏感数据 | 首版不抓取链接；AI 请求逐跳解析/校验地址；默认禁重定向；凭据不跨 origin |
| 凭据泄漏 | Key 进入 `.env`、日志、数据库、备份或 Issue | 外部账户滥用 | Windows 凭据管理器、集中脱敏、泄漏扫描与撤销指引 |
| 更新供应链攻击 | 被篡改依赖或仓库提交 | 代码执行与数据窃取 | 私有仓库权限、受保护分支/标签、lockfile、`npm ci`、审计 |
| 数据破坏 | 迁移、更新、磁盘满、掉电或并发实例 | 求职记录丢失 | 单实例锁、事务、迁移前备份、generation、journal 与单一 active 指针 |
| 分享误泄漏 | 导出的 HTML/Markdown 带私人字段/路径 | 隐私扩散且难撤回 | 默认最小字段、逐项预览、脱敏检测、离线自包含文件 |
| 本机其他用户访问 | 数据目录 ACL 被放宽 | 本地隐私泄漏 | 不主动放宽 ACL，使用当前用户 LocalAppData，文档建议独立账户 |

残余风险：同一 Windows 账户下运行的恶意软件、浏览器扩展、屏幕录制和已解锁设备可以读取用户可见数据；首版无法通过应用层加密消除这些风险。

## 5. 本地服务安全要求

- 生产启动固定监听 IPv4 `127.0.0.1:3210`，不监听 IPv6、`localhost` 别名、`0.0.0.0` 或任何局域网接口。
- 端口 `3210` 被占用时安全失败并说明如何识别/停止占用进程，不自动改端口。固定 origin 是 PWA、IndexedDB、通知授权和 CSRF 边界的一部分。
- `start.cmd` 必须以前台方式托管 Node Server；关闭窗口会转发优雅停止并释放数据库/作业锁。首版不得注册 Windows 服务或托盘常驻，也不得在窗口关闭后保留脱离控制台的后台进程。
- 只接受 `Host: 127.0.0.1:3210`，浏览器入口和允许的 Origin 也固定为 `http://127.0.0.1:3210`；不得接受任意 Host 或 `null` Origin。
- 所有写请求验证 Origin/Referer、CSRF token 和允许的方法、Content-Type、体积上限。
- 不设置允许任意来源的 CORS；不为便利开放 `Access-Control-Allow-Origin: *`。
- 健康检查只返回状态、应用版本与 schema 兼容状态，不返回记录数、路径、错误栈或环境变量。
- 会改变数据或生成导出的路由不得由 GET 触发。
- 响应至少配置合理的 CSP、`X-Content-Type-Options: nosniff`、Referrer Policy 和禁止嵌入策略。
- 启动后自检实际监听地址和端口；与固定 IPv4 origin 不一致时立即停止并记录非敏感错误。

本地监听不能代替请求鉴权边界。恶意网页仍可能尝试访问 localhost，因此 Host、Origin 和 CSRF 控制均为必须项。

## 6. 输入、富文本与链接

- 所有 API 输入使用服务端 schema 校验；客户端校验只用于体验。
- 富文本采用允许列表净化，只保留业务所需标签和属性；禁止脚本、事件属性、内联样式、表单、iframe、SVG、`javascript:` 和危险 data URL。
- 原始 HTML 不直接渲染；Markdown 渲染同样经过 URL 协议与 HTML 净化。
- 外部链接只允许预期协议；打开时使用隔离参数，避免新页面获得 opener。
- 首版粘贴网页链接不自动抓取远程正文。若以后新增抓取，必须单独设计 SSRF、防重定向和下载上限控制。
- AI 响应按攻击者可控文本处理，不允许其指令调用本地工具、读取文件或直接写入正式实体。
- 请求体、富文本和导入单元格均设置长度上限；错误响应不能回显完整原文。

### 6.1 AI 外连与 SSRF

- 普通版本只允许公共 HTTPS AI endpoint；拒绝 URL 用户信息、片段、非默认危险协议和无法规范化的主机。HTTP loopback 只允许显式开发模式、固定 allowlist 且不得携带真实凭据。
- 每次连接和重试都解析 DNS 的全部 A/AAAA 结果；任一结果属于 IPv4/IPv6 私网、loopback、link-local、unspecified、multicast、保留/文档网段、运营商共享地址、IPv4-mapped IPv6 或已知 metadata 地址时整次拒绝。至少显式阻断 `169.254.169.254`、`fd00:ec2::254` 和常见 metadata 主机名。
- 解析通过后把本次连接固定到已批准地址，并核对实际 peer address；TLS 证书与 SNI 仍按原始 hostname 验证。重试必须重新走完整策略，不能信任旧缓存，防止 DNS rebinding。
- 首版禁用自动重定向。未来若开放，限制跳数，并对每一跳重新解析、分类和验证协议/地址；Origin 改变时必须移除 `Authorization`、Cookie 和其他秘密头，任何情况下都不得把 Authorization 转发到不同 origin。
- 响应体使用流式字节上限和超时，错误页不得回显目标响应正文或完整 URL 查询参数。代理环境变量不能绕过同一地址策略。

## 7. 附件与文件系统

仅支持经确认的图片格式和 PDF；SVG 与任意可执行/脚本格式不属于首版。

安全要求：

- 导入时复制到应用管理目录，不能长期引用用户原路径。
- 原始文件名只作为经过净化的显示元数据；磁盘文件名由应用生成的 `object_key` 决定。`object_key` 是已经包含规范小写扩展名的完整相对文件名，任何调用方不得再次追加 `.<ext>`。
- `resolve(stores/<generation>/attachments, object_key)` 后必须再次确认结果精确位于可信根下；拒绝绝对路径、`..`、设备路径、ADS、符号链接、目录联接、特殊文件和非规范扩展名。
- 同时检查扩展名、声明 MIME 和文件签名；不一致时拒绝，不能“修正后继续”。
- 默认上限固定为：单文件 `50 MiB`、单批 `20` 个、当前受管附件总量 `2 GiB`、图片解码 `40 MP`、PDF `500` 页；在完整读取或解码前尽早检查可判断的预算，任一超限均拒绝整项而不修改正式数据。
- 附件严格按以下顺序提交：流式写入用户数据根同卷的 `tmp/uploads/<operation-id>` 并计算大小/哈希 → 对打开句柄 flush 并执行 `fsync`/`FlushFileBuffers` → 关闭句柄并完成签名/MIME 校验 → 按真实格式生成已含小写扩展名的随机 `object_key` → 复核唯一目标 `stores/<generation>/attachments/<object_key>` → 以 **no-replace** 语义同卷原子移动 → 在短数据库事务中登记附件与关联。目标已存在时绝不覆盖，改用新对象键或失败；上传暂存不得写入 generation、`runtime/tmp` 或系统公共临时目录。
- 移动成功但数据库登记失败的文件是孤儿，不能在错误路径中立即猜测删除。孤儿扫描器只处理超过安全等待期（默认至少 24 小时）、不在活动数据库中被任何行引用且不属于进行中操作的内部对象键。
- 永久删除附件时，在删除关系的同一数据库事务写入持久 `file_gc_jobs` outbox；提交后 worker 才按任务中的 `generation_id + object_key` 唯一定位 `stores/<generation_id>/attachments/<object_key>`，复核根路径和预期哈希后幂等删除并确认任务。worker 不拼接扩展名、不按 active generation 猜路径；进程中断、占用或删除失败保留记录重试，绝不能先删文件再提交数据库。
- 提供下载/预览时设置正确 Content-Type、`nosniff` 和安全的 Content-Disposition；不得让上传内容成为同源可执行页面。
- 临时文件、孤儿扫描与 GC outbox 使用不同状态/目录；维护任务必须持锁并记录非敏感结果，不能把软删除仍引用的附件当孤儿。

## 8. 数据库、删除与本地权限

- SQLite 启用外键与适当的完整性检查；高风险多表写入使用事务。
- 采用单实例锁，禁止两个本地服务同时写同一数据库。
- 数据库与附件始终从同一 `stores/<generation>` 打开，活动 generation 只由 `runtime/active.json` 指定。浏览器请求、导入内容和环境参数都不能提供 generation 或绝对路径。
- 恢复/更新激活只在服务停止、句柄关闭和独占维护锁持有时进行；先落盘 `activation-journal.json`，再单文件替换 `active.json`。启动时必须完成 journal 或回到上一已验证 generation，不能分别选择数据库和附件。
- 普通删除进入回收站 30 天；恢复保留关联。永久删除需二次确认，并在备份仍可能含该内容时明确提示。
- 自动备份和 previous generation 的保留期意味着永久删除无法立即清除历史副本；界面和文档必须解释该边界，并分别提供删除本地备份、清理已验证旧 generation 的明确操作。清理 previous generation 会失去对应的快速回退能力，必须再次确认。
- 应用不得主动把数据目录 ACL 放宽给 `Everyone`、其他本地用户或网络共享。
- 数据库首版不做应用级加密。设置页应说明保护依赖 Windows 账户，并建议启用设备加密。
- 崩溃恢复不得把数据库副本写到系统公共临时目录；临时文件仍应在应用数据根下的 `tmp` 目录。

## 9. API Key 与可选 AI

- API Key 通过 Windows 凭据管理器保存，以应用命名空间和连接 ID 区分；数据库只保存非秘密的接口配置和凭据引用 ID。
- Key 禁止进入源码、`.env`、命令行参数、URL、数据库、配置 JSON、日志、备份、导出、错误页面、剪贴板历史和分析事件。
- 凭据读取应尽量晚、使用后尽快释放引用；不得将完整 Key 回传浏览器。界面只显示“已配置”和不可逆的短掩码标识。
- 用户删除连接时同时删除凭据；删除失败必须提示，而非仅删除数据库引用。
- AI 调用必须由用户显式触发。发送前列出字段、目标服务和模型；默认不发送私人面试记录、联系人、会议链接和附件。
- 默认要求 HTTPS。自定义 HTTP 端点仅可在明确的本机开发模式使用，并持续显示风险提示；不得作为普通配置隐藏开放。
- 处理 401/403 时提示检查或撤销 Key；不得把响应头、请求体或 Key 写日志。
- 发现泄漏时立即停止使用、在供应商处撤销并更换 Key，随后清理日志/备份并执行金丝雀扫描。

## 10. 备份与恢复安全

- 普通 ZIP 导出前必须提示其中包含敏感信息；经聊天工具或网络传输时建议使用强加密备份。
- 加密包遵循 [ADR-0004](adr/0004-backup-format-and-encryption.md)：Argon2id v1.3（version `0x13`/19，32 字节 key，默认 64 MiB/`t=3`/`p=1`）与 libsodium `crypto_aead_xchacha20poly1305_ietf` 变体（24 字节 nonce、16 字节 tag），自描述 header 作为 AAD，内部负载是版本化完整 ZIP。禁止 ZipCrypto 和自制密码学。
- 备份密码只存在于本次操作内存，不保存、不记录、无法找回。
- 自动备份位于当前用户应用目录，不使用交互式密码；其安全性依赖 Windows 账户和设备加密。
- 写备份时先写临时文件，计算 SHA-256 并校验可读后原子改名；不得先删除旧备份。
- 解密前限制 envelope header 和 Argon2 参数；认证完成前不解析 ZIP。错误密码与 header/密文/tag 篡改统一报错，不能形成 oracle。
- 普通 ZIP 的 `checksums.json` 只覆盖 `data.json` 与 `attachments/**`，用于检测意外损坏，不提供签名或抗恶意篡改信任；只有加密 envelope 对内部 ZIP 整体认证。
- 恢复前验证 manifest、data JSON Schema、格式/schema 兼容性、成员哈希和集合、附件数、成员数、单项/总解压大小与压缩比。
- 拒绝绝对路径、父目录跳转、重复规范化路径、符号链接、硬链接和未知特殊成员。
- 在新的 `stores/<generation>` 恢复并运行完整性检查；服务停止后通过 journal 和单一 `runtime/active.json` 指针提交。失败时回到完整旧 generation，禁止宣称同时原子替换两个路径。
- 应用无法启动时只通过发布版 `restore.cmd` 进入恢复协议；`setup.cmd --repair` 只能做只读诊断和引导，不能替代恢复或切换 generation。
- API Key、凭据引用的秘密值和备份密码永不进入备份。

## 11. 日志、诊断与遥测

本地阶段不包含默认遥测，不自动上传崩溃报告或使用行为。

允许记录：时间、应用版本、事件类型、内部关联 ID、耗时、成功/失败、归一化错误码和必要堆栈（生产构建应去除请求内容）。

禁止记录：JD/面经/备注原文、联系人、会议链接、URL 查询参数、导入单元格、附件内容与原始文件名、API 请求/响应正文、Authorization/Cookie、API Key、备份密码、完整用户路径。

- 建立集中式结构化日志与脱敏函数，禁止业务代码直接拼接异常对象。
- 日志默认轮换并设置短期保留；建议默认最多 7 天或受控总大小，以先到者为准。
- “复制诊断信息”先展示预览，只包含版本、错误码和脱敏环境摘要。
- GitHub Issue 模板明确要求不要上传数据库、备份、附件、完整日志或真实截图；提供最小复现模板。
- 测试用金丝雀值扫描日志、导出、备份和 CI artifact，作为发布门禁。

## 12. GitHub 与依赖供应链

- 内测期仓库保持私有，只邀请需要体验的朋友；禁止共用个人访问令牌。
- 主分支启用保护和必要检查；发布使用可追溯标签，发布说明标注提交 SHA。
- 提交 `.gitignore` 覆盖数据库、WAL/SHM、附件、备份、日志、`.env*`、凭据导出、测试下载和本地配置。
- CI 只能使用合成夹具；构建产物不得打包用户目录或开发机配置。
- 依赖由 lockfile 固定并使用 `npm ci`；新依赖先检查维护状态、许可证、安装脚本和权限范围。
- 定期运行依赖审计；高危漏洞若不可立即修复，必须禁用受影响功能或阻断发布，并记录到期日。
- 更新脚本只接受配置的 Git remote/upstream 和快进更新；检测脏工作区时退出，不删除用户源代码改动。

## 13. 隐私控制与数据生命周期

- 默认最小化收集：可选字段不因方便而变为必填。
- 搜索、统计和规则提取都在本机执行；只有用户明确触发 AI 时才发生外发。
- 分享采用逐字段选择和预览；导出一旦发送，应用无法远程撤回，必须在确认页提示。
- 用户可完整导出自己的业务数据和附件；API Key 不随之导出。
- 用户可清空当前数据、回收站、本地备份和不再活动的旧 generation。该操作需分别确认并说明不可恢复范围；“清空当前数据”不能伪装成已经抹除仍保留的历史副本。
- 卸载/删除仓库不会自动删除 `%LOCALAPPDATA%` 数据；反之，清空数据不应删除源码仓库。运维文档必须分别说明。

## 14. 安全验收清单

每个发布候选至少确认：

- [ ] 服务仅监听回环地址，局域网设备无法连接。
- [ ] Host、Origin、CSRF、CORS 与安全响应头测试通过。
- [ ] 富文本、Markdown、导入和 AI 输出的 XSS 语料被阻断。
- [ ] 附件与备份路径遍历、符号链接、大小耗尽测试通过。
- [ ] 数据库迁移、更新失败和恢复失败均保持原数据可用。
- [ ] API Key 金丝雀未出现在数据库、配置、日志、导出、备份、截图和 Git 历史。
- [ ] 仓库与构建产物不含真实用户数据和本地路径。
- [ ] 删除、回收站、自动备份保留和分享不可撤回边界有清晰提示。
- [ ] 依赖审计没有未处置的高危问题。

## 15. 安全事件处理

1. 立即停止受影响版本和外部 AI 连接，不继续反复尝试。
2. 保留最小、脱敏的版本号、错误码和时间信息；不要复制真实数据到 Issue。
3. 若可能泄漏 API Key，先在供应商处撤销，再更换本机凭据。
4. 从最后一份已校验备份恢复到隔离目录，确认完整后再切换。
5. 修复需包含回归测试、受影响版本范围、用户可执行的检查/清理步骤和发布说明。
6. 若仓库曾提交秘密或真实数据，仅删除当前文件不够；应撤销凭据、限制仓库访问，并按 Git 历史清理流程处理。
