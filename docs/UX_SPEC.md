# 秋招进度板：UX 与交互规格

> 适用产品：`campus-hire-tracker` Windows 本地版
> 需求来源：[PRD](PRD.md)
> 术语来源：[术语表](GLOSSARY.md)
> 本文定义用户可见行为；视觉稿可以调整装饰细节，但不得改变本文的信息优先级、流程和状态语义。

## 1. 体验目标

界面要让用户在高压力求职周期中获得确定感，而不是再制造一套需要维护的复杂系统。每个一级页面只承担一个主要问题：

- **今日**：现在最需要处理什么？
- **申请**：所有岗位分别推进到哪里？
- **日历**：哪些时间会冲突或临近？
- **资料库**：JD、面经和复盘在哪里？
- **招聘会**：参加前准备什么，参加后跟进什么？

全局交互遵循以下顺序：先暴露风险，再提供行动；先允许快速捕获，再引导补全；先确认事实，再改变阶段；先说明影响，再执行删除、恢复或外部发送。

## 2. 体验范围与约束

- 首版是单机单用户产品，不显示头像、登录、团队、云同步或在线状态。
- 正式支持 Windows 桌面浏览器和 Windows PWA。窄屏布局必须可用，以支持窗口分屏并为未来移动端做准备，但不承诺手机能连接本机服务。
- 界面默认简体中文；架构预留国际化，但首版不显示不可用的语言选择器。
- 所有用户数据默认本地保存。涉及 AI、系统日历、分享文件的外部边界必须在操作前明确提示。
- 功能按 PRD 的三个里程碑开放。尚未实现的入口默认不展示；如为引导必须展示，则使用“即将提供”且不可产生误导性可点击状态。

## 3. 信息架构

### 3.1 一级与二级导航

| 层级 | 导航项 | 默认路由 | 核心任务 | 上线里程碑 |
| --- | --- | --- | --- | --- |
| 一级 | 今日 | `/today` | 处理逾期、今天、近期、复查和待补项 | M1 |
| 一级 | 申请 | `/applications` | 通过看板或表格管理岗位申请 | M1 |
| 一级 | 日历 | `/calendar` | 查看月历和日程，发现冲突 | M1 |
| 一级 | 资料库 | `/materials` | 搜索和维护 JD、外部资料、个人记录 | M2 |
| 二级 | 招聘会 | `/fairs` | 准备、参加和复盘招聘会 | M2 |
| 二级 | 统计 | `/analytics` | 查看基础漏斗、渠道和趋势 | M3 |
| 二级 | 归档 | `/archive` | 查阅已结束申请并复盘 | M2 |
| 二级 | 回收站 | `/trash` | 恢复或永久删除记录 | M2 |
| 系统 | 设置 | `/settings` | 管理偏好、通知、数据、AI 和关于信息 | 分阶段 |

申请详情使用 `/applications/:applicationId`；招聘会详情使用 `/fairs/:fairId`；资料详情使用 `/materials/:materialId`。不存在或已删除的 ID 必须进入明确的未找到状态，不得悄悄跳回列表。

### 3.2 桌面导航

宽度 `≥ 1200px` 时使用 240px 固定左侧栏：

1. 顶部显示产品名“秋招进度板”。
2. 一级导航按“今日、申请、日历、资料库”排列。
3. 分隔线下显示“招聘会、统计、归档”。
4. 底部固定“设置”；回收站放在设置的数据管理区，同时可由归档页进入。
5. 当前页面使用形状、字重和文字共同表示，不只改变颜色。

页面顶部工具栏包含：当前页标题、可选的页内筛选、全局搜索按钮、全局“新建”按钮。工具栏可以在页面滚动时保持可见，但不能遮挡锚点内容。

宽度 `768–1199px` 时左侧栏收为 72px 导航轨：保留图标和无障碍名称，悬停与键盘聚焦显示文字提示；不得只凭图标让用户猜测含义。用户可临时展开，不改变内容区域的阅读顺序。

### 3.3 窄屏导航

宽度 `< 768px` 时使用底部导航，固定五项：今日、申请、日历、资料、更多。底部栏高度至少 64px，并处理系统安全区。

“更多”页面列出招聘会、统计、归档、回收站和设置。全局新建使用底部栏上方的浮动按钮；打开键盘或全屏编辑器时自动避让，不覆盖主要操作。

窄屏模式主要用于 Windows 窄窗口和未来兼容验证。涉及手机能力时，界面必须明确“首版通过系统日历接收手机提醒”，不能暗示本地应用会在手机后台运行。

### 3.4 全局搜索与新建

- 桌面点击搜索或按 `Ctrl+K` 打开全局搜索；窄屏从页面顶部或“更多”进入。
- 搜索覆盖申请、公司、资料和招聘会；结果按类型分组，每项显示命中上下文。
- 桌面在非输入状态按 `N` 打开全局新建；输入框、编辑器和组合键场景不得误触。
- 全局新建第一层允许选择“岗位申请、事件、招聘会、资料”；在 M1 仅显示已经可用的类型。
- 所有快捷键都必须有可见按钮替代，并在“设置 > 快捷键”或帮助提示中列出。

## 4. 响应式布局规则

### 4.1 断点与内容宽度

| 区间 | 导航 | 页面边距 | 主要行为 |
| --- | --- | --- | --- |
| `≥ 1200px` | 240px 侧栏 | 32px | 多栏详情、完整表格、月历 |
| `768–1199px` | 72px 导航轨 | 24px | 详情可降为单栏，表格允许受控横向滚动 |
| `< 768px` | 底部导航 | 16px | 单栏、卡片列表、日程列表、全屏编辑 |

- 普通阅读/编辑内容最大宽度为 1200px；看板和月历可以占满可用宽度。
- 任何断点下都不得出现页面级无意横向滚动。看板列容器和中等屏表格可以在自身区域内横向滚动，并显示滚动提示。
- 200% 浏览器缩放时不得丢失内容或主要操作；允许布局按窄屏规则重排。

### 4.2 响应式转换

- **看板**：各列保持至少 280px 宽，横向滚动，不把卡片压缩到不可读；窄屏顶部提供阶段选择器，可直接跳到某列。
- **表格**：`≥ 768px` 使用表格；`< 768px` 自动改为信息卡列表，不通过横向滚动模拟完整桌面表格。
- **月历**：`≥ 768px` 可显示月历与右侧/下方日程；`< 768px` 默认只显示日程列表，月份通过紧凑日期选择器切换。
- **详情页**：宽屏使用主内容加 320px 上下文侧栏；中窄屏改为单栏，状态摘要置顶。
- **对话框**：桌面居中，宽度不超过 640px；复杂导入和编辑流程最大 960px。窄屏使用全屏页或底部抽屉，破坏性确认不得因滑动手势被意外提交。
- **表单**：宽屏可以两列排列互不依赖的短字段；有条件关系、错误解释或长文本的字段始终单列。

## 5. 全局应用框架

### 5.1 启动状态

应用启动按顺序显示：

1. 产品标识与“正在打开本地数据”。
2. 若需迁移，显示当前步骤和“请勿关闭”说明；不得显示虚假百分比。
3. 成功后进入上次页面；首次使用进入引导。
4. 失败时进入专用恢复页，说明数据是否已修改、最近备份位置、重试与查看日志操作。

数据库迁移、恢复和更新期间禁止进入可能写入数据的业务页面。

### 5.2 顶部状态反馈

- 自动保存状态显示在当前编辑上下文附近，而不是只放全局通知：`未保存`、`保存中…`、`已保存 14:32`、`保存失败，重试`。
- 从 M1 起，只有长文本尚未成功保存的内容写入固定 origin IndexedDB 的 `EditorRecoveryDraft`。数据库保存成功后清除对应草稿；重新加载时若草稿更新，先比较再让用户选择“恢复未保存内容”或“保留已保存版本”。它不属于正式数据、不进入备份，M1 也不注册 Service Worker。
- 一次性成功使用轻量提示条；可撤销操作的提示条至少保留 8 秒，并提供明确“撤销”按钮。
- 跨页面持续任务（导入、备份、附件复制）显示全局任务面板；关闭面板不取消任务。
- 本地服务断开时顶部显示持续横幅“与本地服务的连接已断开”，正式数据编辑转为只读；M3 允许保存独立的快速草稿。

### 5.3 全局日期与时间

- 默认按 Windows 当前时区展示，并在事件编辑器中显示时区名称。
- 同一年日期显示为“9月12日 周六”；跨年时包含年份；时间使用 24 小时制。
- 相对时间只能作为辅助，例如“明天 14:00”，旁边或无障碍名称中必须提供绝对日期。
- 截止与复查语义分开：硬期限写“截止时间”，等待后的检查点写“复查日期”。

## 6. 首次使用与示例数据

### 6.1 引导页结构

首次使用是一个最多三步、可跳过的流程：

1. **说明用途**：一句话解释产品围绕“申请、日程、下一步”工作，并声明数据保存在本机。
2. **选择开始方式**：主操作“创建第一条申请”，次操作“导入现有表格”；另提供“载入示例看看”。未实现导入时明确标注 M2，而不是允许进入死路。
3. **提醒策略**：说明应用内提醒与系统日历的区别；M3 前仅显示说明，不提前索取浏览器通知权限。

该步骤同时提供“稍后导出”和“了解系统日历导出”。ICS 导出从 M1 即可用；此处不得把浏览器通知描述为应用关闭后的可靠渠道。

用户可以跳过，跳过后进入“今日”空态。引导不得强迫填写完整资料、开启通知或配置 AI。

### 6.2 示例数据规则

- 示例至少覆盖一条有下一步的申请、一条等待复查的申请和一条近期面试事件。
- 所有示例卡片显示“示例”标记，统计默认排除。
- 页面持续提供“删除全部示例”操作，删除时只影响被标记的示例记录。
- 用户开始创建真实数据后，不自动删除示例，也不混淆二者。

## 7. “今日”页面

### 7.1 页面目标与结构

“今日”是默认首页，内容顺序固定：

1. **逾期与冲突**：已过截止/复查时间、相互重叠的未取消事件。
2. **今天**：今天发生或截止的事件和下一步。
3. **未来 7 天**：从明天起七个自然日内的安排。
4. **等待复查**：已到或临近复查日期的等待申请。
5. **缺少下一步**：非归档且既无下一步也无等待状态的申请。

顶部摘要只显示有意义的数字，例如“2 项逾期 · 1 处冲突 · 今天 3 项”。没有风险时使用中性文本，不使用庆祝式打卡动画。

### 7.2 卡片内容与排序

每个事项卡片至少显示：

- 风险/事件类型文本与图标；
- 绝对日期和时间；
- 公司 + 岗位，或招聘会名称；
- 相关阶段、优先级；
- 一个主要操作和不超过两个次要操作。

排序规则：

- 逾期项先按硬截止、事件、复查排序，同类按最早逾期时间，再按高/中/低优先级。
- 冲突组按最早开始时间显示为一个组合卡，展开后列出全部冲突事件。
- 今天和未来 7 天按开始/截止时间升序，全天项置于当天有时刻项之前。
- 等待复查按复查日期升序，再按优先级。
- 缺少下一步按高、中、低优先级，再按最久未更新排序。

同一个具体事件只出现在一个时间分区。某申请可以同时有关联事件和“缺少下一步”，但两张卡必须标注各自原因，不能看起来像重复数据。

### 7.3 就地操作

- 下一步可以“完成”“改期”“打开申请”。点击“完成”后立即要求选择新下一步、转为等待中或保留待补。
- 等待复查可以“继续等待”“设置下一步”“打开申请”。继续等待必须选择新复查日期。
- 事件可以“查看”“改期”“标记结果”；结束事件后只显示阶段确认建议。
- 冲突卡提供“查看日历”和逐项“改期”，不提供自动改期。

### 7.4 空态

- 整页无数据：标题“还没有求职记录”，说明从创建申请开始；主按钮“创建第一条申请”，次按钮“导入表格”。
- 有申请但今天无事项：标题“目前没有需要处理的事项”，提供“查看全部申请”和“新建事件”。
- 某一分区为空时默认不渲染空容器；“逾期与冲突”可以保留简短的“暂无风险”摘要，但不占据大面积首屏。

## 8. “申请”页面

### 8.1 顶部控制区

从左到右包含：看板/表格分段控件、关键词搜索、筛选、排序（表格）、“只看待补”快捷筛选、新建申请。活跃筛选条件显示为可逐项移除的标签，并提供“清除全部”。

看板和表格共享搜索与筛选状态。视图偏好保存到本机；页面刷新或从详情返回后恢复滚动位置和筛选。

### 8.2 看板

- 默认显示机会池、准备投递、已投递、测评/笔试、面试中、Offer 六列；归档通过独立入口查看。
- 列头显示阶段名和当前筛选下数量，允许折叠但不允许用户改变固定阶段顺序。
- 卡片显示公司、岗位、批次（有值时）、优先级、来源、下一步/等待/待补状态、最近事件和冲突标记。
- 卡片整块可聚焦并打开详情；内部按钮必须有独立可点击区域，不能因冒泡误开详情。

拖动规则：

1. 拖动开始时原位置保留占位。
2. 放入新列后显示目标阶段文字并保存。
3. 进入归档不通过直接拖入隐藏列，必须使用“归档”操作并选择原因。
4. 保存成功后提示“已移至「面试中」”，提供 8 秒撤销。
5. 保存失败时卡片返回原列，焦点回到卡片，显示原因和重试。
6. 卡片菜单提供“移动到阶段…”作为键盘和触屏的等价操作。

### 8.3 表格

默认列为公司、岗位、阶段、优先级、下一步/等待、最近事件、来源、更新时间。用户可以显示批次、地点、标签和创建日期，但列偏好只存本机。

- 表头可排序；排序方向有文字化无障碍名称。
- 行选择用于导出或批量归档；首版不提供无确认的批量阶段推进。
- 行内阶段选择、优先级和下一步允许快速编辑；保存失败恢复原显示并保留输入草稿。
- 窄屏转为卡片列表，每张卡保持与看板卡相同的核心信息，并提供“更多操作”。

### 8.4 列表空态

- 无任何申请：引导创建或导入。
- 筛选后为空：显示“没有符合这些条件的申请”，列出当前条件，主操作“清除筛选”。
- 仅当前阶段为空：看板列显示轻量占位“暂无申请”，允许通过按钮新建并预选该阶段。

## 9. 快速创建申请

### 9.1 表单结构

打开后焦点进入“公司”。第一屏只包含：

- 公司（必填）；
- 岗位（必填）；
- 招聘批次（可选）；
- 主按钮“创建申请”；
- 展开项“添加更多信息”。

展开后显示阶段（默认机会池）、优先级（默认中）、来源、原始链接、截止时间、下一步行动/等待状态和标签。来源默认“未填写”；选择“自定义”后必须填写自定义值，不能用“自定义”代替未填写。M1 的来源菜单不显示“招聘会”，M2 上线招聘会实体后才显示该选项并要求选择具体招聘会。

M3 增加“粘贴内容”页签。解析结果在同一表单中以建议值显示，字段级标注来源；未经用户点击创建不得写入正式数据。

### 9.2 重复警告

输入离开岗位或批次字段后进行非阻塞检查。发现相同“公司 + 岗位 + 批次”时，在表单内展示已有记录的阶段、更新时间和打开链接。

点击创建时仍存在重复，则确认对话框提供：

- 主操作“查看已有申请”；
- 次操作“仍然创建”；
- “返回修改”。

“仍然创建”是显式选择，不能通过按 Enter 意外触发。

### 9.3 创建后反馈

- 若已设置下一步或等待状态：提示创建成功，提供“打开详情”。
- 若处于待补：提示“申请已创建，还缺少下一步”，主操作“现在设置”，次操作“稍后处理”。选择稍后后，该申请立即进入今日的缺少下一步区。
- 连续录入场景提供“再创建一条”，但不默认保留公司之外的字段；是否保留公司由用户明确选择。

## 10. 申请详情页

### 10.1 固定摘要

页面顶部显示返回入口、公司、岗位、批次和操作菜单。宽屏右侧上下文栏、窄屏顶部摘要卡持续显示：

- 主阶段；
- 高/中/低优先级；
- 下一步行动，或等待状态与复查日期，或“缺少下一步”警告；
- 最近一项未来事件；
- “更新进度”主操作。

状态摘要滚动吸顶时必须缩短但不消失。Offer 阶段仍显示下一步/等待；归档状态显示归档原因和日期，并将编辑主操作替换为“恢复为活跃”。

### 10.2 标签页

固定顺序为“概览、流程、资料、时间线”。标签页 URL 应能直接定位，以便刷新后保持上下文。

#### 概览

显示和编辑公司、岗位、批次、地点、来源、原始链接、标签、优先级、通用备注、创建与更新时间。字段自动保存；来源链接在打开前显示目标域名。

#### 流程

按“当前行动 → 主阶段 → 事件 → 面试轮次”组织：

- 当前行动区域只能在“下一步”和“等待中”之间选择；待补状态使用高可见但不羞辱用户的提示。
- 进入等待中时只有复查日期/时刻必填，提交后由系统创建或更新对应的复查事件；“等待对象”和说明均明确标为可选。
- 阶段区展示固定步骤条和完整变更历史入口。
- 事件按未来、过去、已取消分组。
- 面试轮次按用户定义顺序排列，可以自由命名和调整顺序。

#### 资料

分为 JD 快照、外部资料、个人面试记录三个区域。每区有独立新建按钮和说明；禁止用单一“备注”替代类型。

#### 时间线

倒序显示审计事实。每条包含发生时间、动作、变更前后摘要和来源（用户操作、导入、系统建议确认）。筛选项至少包含阶段、行动、事件和资料。时间线不是聊天框，不提供直接编辑。

### 10.3 更新进度流程

点击“更新进度”打开一个有顺序的面板：

1. 选择新阶段或保持不变。
2. 可选记录相关结果或备注。
3. 设置新下一步、进入等待中，或明确保留待补。
4. 预览将写入的变化并确认。

事件结束后打开此面板时可以预选建议，但不得预先提交。用户关闭面板不产生任何状态变化。

完成或移除当前行动/等待状态后，若用户没有立即补上后续安排，界面必须要求明确选择“稍后补充”才进入待补。快速创建、不完整导入/迁移和归档恢复也可以产生待补，但不能由普通保存失败暗中产生。

### 10.4 面试轮次的取消、删除与附件

- “取消轮次”确认页默认保留关联事件，并以未勾选选项提示“同时取消关联事件”；轮次取消成功不暗中改变事件状态。
- “删除轮次”进入回收站。默认方案是在同一事务内将该轮次唯一的面试事件改为直接关联所属申请，提醒与历史保持不变；用户可以明确改选“轮次与事件一同进入回收站”。确认页必须预览实际影响。
- 面试轮次不直接上传附件。轮次相关图片或 PDF 必须添加到该轮次的“个人面试记录”中；界面可提供快捷创建记录，但生成的数据关系仍是 `InterviewRound → INTERVIEW_NOTE → Attachment`。

## 11. 日历与事件

### 11.1 页面结构

桌面顶部包含“今天”、上一周期、下一周期、月份标题、月历/日程切换、事件类型筛选、“导出到系统日历”和“新建事件”。

- 月历单元格显示日期、最多三项事件摘要和“还有 N 项”。
- 右侧或下方日程显示选中日期的完整列表。
- 日程视图按日期分组，跨日事件在每天显示连续标识但只保留一个业务实体。
- 窄屏默认日程，顶部使用横向日期条或日期选择器，不渲染挤压后的七列月历。

### 11.2 事件视觉语义

事件类型使用图标 + 短标签；颜色只是辅助。取消事件使用“已取消”文本和弱化样式，过去未标记结果的事件显示“待确认结果”。冲突事件显示可识别的“时间冲突”标记。

### 11.3 新建/编辑事件

字段按以下顺序：事件类型、标题、关联对象、日期、是否全天、开始时间（必填）、结束时间（可选）、时区、地点/会议链接、提醒、备注。

- M1 的面试和测评/笔试默认要求关联申请；允许先快速创建申请再返回事件表单。M2 启用面试轮次后，面试事件可改为关联具体轮次并由轮次展示所属申请，但不得同时保存两套冲突的直接关联。
- 招聘会事件关联招聘会；投递截止关联申请。
- 未填写结束时间时将事件保存为时间点，界面不得自动补默认时长；填写后若结束早于开始则禁止提交并就地说明。
- 与现有事件的时间区间/时间点冲突按数据模型的统一规则判断。在保存按钮上方列出冲突项；主操作文字改为“仍然保存”，且首次警告不能被 Enter 意外跳过。
- 改期保留原时间的历史，取消需要可选原因；删除进入回收站。

### 11.4 事件结束后的确认

到达结束时间后，事件卡显示“确认结果”，用户可以标记完成、取消或仍在进行。完成面试或笔试后，界面可以询问“是否需要更新申请阶段或下一步？”，选项为“现在更新”和“暂不”；暂不不会改变阶段，但申请若无行动将进入待补队列。

### 11.5 系统日历导出

ICS 是 M1 的可靠提醒出口，而不是增强功能。事件详情菜单提供“导出此事件”；日历页提供“导出当前筛选”和“导出全部未来事件”。

导出对话框必须：

1. 列出将导出的事件数量和日期范围。
2. 预览标题、时间、地点、链接、描述和提醒。
3. 默认排除普通备注、复盘、面试官和其他敏感正文。
4. 说明“这是单向导出；系统日历中的修改不会回写”。
5. 生成后提供“打开所在文件夹”，不声称已经自动加入系统日历。

M1 覆盖当时已有的面试、测评/笔试、投递截止和跟进/复查事件；M2 新增招聘会后，同一入口自动支持招聘会事件，无需新的导出流程。

## 12. 资料库与编辑器

### 12.1 资料列表

顶部提供关键词、资料类型、公司/岗位、标签和更新时间筛选。结果默认按最近更新排序，显示类型、标题、摘要、关联对象、附件数量和更新时间。

用户可以从资料库创建资料，也可以从申请或面试轮次上下文创建。全局创建时，在保存前必须选择至少一个关联对象。

### 12.2 富文本编辑器

- 工具栏只保留标题、加粗、斜体、列表、引用、代码和链接等必要能力。
- 粘贴网页内容时清除不安全样式、脚本和跟踪元素，保留可读结构；在写入前允许预览。
- 编辑器持续显示草稿/保存状态，并沿用 M1 的 `EditorRecoveryDraft`：只保护尚未成功保存的长文本，不进入备份，也不提供离线正式编辑。浏览器刷新后若草稿比数据库更新，必须让用户比较“恢复草稿”和“保留已保存版本”。
- Markdown 导出是显式操作；不要求用户直接编辑 Markdown 源码。

### 12.3 三类资料的差异

- **JD 快照**：正文必填；标题默认“公司 + 岗位 + JD”；显示捕获日期和原始链接；允许保存多个历史快照，最新不覆盖旧版。
- **外部资料**：标题必填，并要求有效来源 URL 或正文至少一项；首版不自动抓取远程正文，标题和摘要由用户填写或从用户已粘贴的正文中提取。
- **个人面试记录**：正文必填且必须关联具体面试轮次，所属申请由轮次推导；顶部持续显示“默认不分享”。若尚无轮次，先在当前表单中快速创建轮次再继续。

### 12.4 附件

附件区同时提供拖放和“选择文件”。上传前显示支持范围（图片、PDF）和大小限制；复制过程中显示文件名、进度和取消。

- 校验失败显示具体原因并保留其他成功文件。
- 打开附件使用应用内安全预览或系统默认查看器；不在富文本中执行 PDF 脚本。
- 找不到或校验损坏时显示占位、预期文件名和“从备份恢复/移除引用”操作，不让整个页面崩溃。
- 附件入口只出现在资料上；面试轮次页面的快捷入口实际打开或创建该轮次的个人面试记录，不建立轮次到附件的直接关系。

## 13. 招聘会

### 13.1 列表

默认分为“即将参加”和“已经参加”；另有“全部”筛选。卡片显示名称、日期时间、地点、参加状态、目标公司数量和会后待跟进数量。

空态说明招聘会能关联多个公司和岗位，主操作“添加招聘会”。产品不暗示会自动抓取外部招聘会信息。

### 13.2 详情

详情按以下区域排列：

1. 基本信息：名称、时间、地点、链接、参加状态。
2. 参会目标：公司与岗位清单，每项可标记优先级、现场状态和笔记。现场状态固定显示为“未接触”（`NOT_CONTACTED`）、“已接触”（`CONTACTED`）、“需跟进”（`FOLLOW_UP_NEEDED`）、“不再考虑”（`NOT_INTERESTED`）。
3. 现场笔记：支持自动保存的富文本。
4. 会后跟进：尚未建档、已创建申请、无需跟进三种明确结果。

从目标岗位点击“创建申请”时打开已预填的快速创建表单；创建完成后原地更新为已关联，提供打开申请入口。重复警告规则与全局新建一致。

## 14. 归档与回收站

### 14.1 归档

归档是业务结束状态，不等于删除。页面使用与申请表格相似的布局，默认显示归档原因、归档日期、最终阶段前状态和来源。

- 归档操作必须选择拒绝、放弃、撤回或其他；“其他”出现必填说明。
- 确认文案说明申请将从活跃看板和提醒中移除，但事件、资料和时间线保留为历史事实；归档不会把事件自动标记为取消。恢复后，仍在未来且有效的事件会重新进入提醒。
- 恢复为活跃时，用户必须从任一非归档阶段中选择目标；“归档前阶段”仅预选为建议，可以改选。随后设置下一步、等待状态或明确接受待补标记。

### 14.2 回收站

回收站按删除日期倒序显示实体类型、名称、删除来源和剩余天数。页面顶部说明“删除项保留 30 天”。

永久删除确认必须另列出“旧 generation/备份中可能仍有副本”。设置页分别管理当前数据、旧 generation 和备份；清理旧 generation 前展示占用空间及“将失去对应版本快速回退”的二次确认，不能用一个含义不清的按钮同时清除三者。

- 单项恢复显示将恢复的关联和可能冲突。
- 同名或重复冲突时，恢复确认页必须让用户选择“合并到现有记录”或“使用建议后缀重命名后恢复”；后缀由系统预填但可编辑。不得静默选择，且两条路径都应能完成恢复，不能让重复名称形成永久阻塞。
- 永久删除按钮与恢复按钮在视觉和位置上清楚区分。
- 永久删除确认要求输入对象名称，或在批量场景输入固定确认词；确认页列出将删除的附件数量与不可恢复说明。
- 自动到期清理前在本地展示待清理摘要并要求确认；用户可以延后，不制造虚假紧迫感。

## 15. 搜索、筛选与统计

### 15.1 全局搜索

搜索框输入 2 个字符后开始本地搜索；按 Enter 可以立即搜索 1 个字符。结果分为申请、公司、资料、招聘会，单组最多先显示 5 条，并提供“查看全部”。

- 命中词高亮必须保持可读对比度，不能改变原始数据。
- 键盘上下键移动结果，Enter 打开，Escape 关闭并把焦点还给触发按钮。
- 无结果显示原关键词和“清除搜索/创建申请”操作。
- 索引暂不可用时降级为标题字段搜索并明确提示，不返回伪装成完整结果的空列表。

### 15.2 筛选

所有组合筛选使用“并且”关系；同一个多选维度内部使用“任一”关系。例如：阶段为已投递或面试中，并且优先级为高。

日期范围必须标注筛选的是截止、事件、复查还是更新时间。清除筛选恢复默认视图，不清除用户保存的列偏好。

### 15.3 统计

统计页顺序为：当前各阶段数量、历史漏斗、来源结果、投递/面试时间趋势。每个可视化下方提供一句文本总结和“查看数据表”。

- 统计页持续显示范围和排除项，例如“已排除示例与回收站数据”。
- 图表点击只能形成筛选或打开明细，不修改业务数据。
- 样本过少时展示事实数字，不生成带误导性的百分比趋势。

## 16. 导入、导出与备份体验

字段和文件协议以 [导入、导出与备份协议](IMPORT_EXPORT_SPEC.md) 为准，本节只定义交互。

### 16.1 CSV/Excel 导入

导入使用不可跳步的五步流程：

1. 选择文件与工作表。
2. 识别编码、表头、日期和分隔符。
3. 映射源列到标准字段。
4. 预览逐行结果、错误、警告、重复项和预计数量。
5. 最终确认并执行单事务导入。

页面顶部显示步骤和当前文件名，但不得把文件内容写入日志。阻塞错误用红色图标 + 文本，警告用不同图标 + 文本；不得只涂整行颜色。

执行过程中离开页面需要确认。失败后显示“没有写入任何记录”或准确说明回滚状态；成功后显示创建、更新、跳过数量和“撤销本次导入”。

### 16.2 导出

- 申请列表只导出 CSV：先选择“当前筛选”或“全部申请”，预览行数和字段。CSV/XLSX 仅是导入支持范围，界面不得出现 XLSX 导出入口。
- ICS 从 M1 即可导出单个事件、当前日历筛选或全部未来事件；预览每个事件将进入日历的摘要、地点、链接和提醒，默认隐藏敏感备注。
- 脱敏分享逐字段勾选，敏感字段默认关闭，预览是生成按钮的前置步骤。
- 保存成功后显示绝对保存位置，并提供“打开所在文件夹”；取消系统文件对话框不显示错误。

### 16.3 备份与恢复

设置页数据区按里程碑开放：M1 显示最近一次成功手动备份、备份目录、手动备份与恢复；M2 再增加最近一次成功自动备份和保留数量。

- M1 已提供完整备份 v1 和 `restore.cmd`；备份预览明确尚未上线的业务表会以空数组保留契约位置。M2 在同一 v1 契约内加入实际附件、每日轮换和可选强加密，不另设不兼容的“基础备份”格式。
- 创建普通 ZIP 前显示敏感信息提示；“使用密码保护”展开密码与确认字段，并说明密码无法找回。
- 恢复先在服务运行时只读显示读取、校验、兼容性与内容摘要；用户最终确认后，界面明确进入“停止服务 → 创建并校验恢复前快照 → 构建候选 → 切换 → 一致性检查”的维护阶段。
- 选择文件后、最终确认前不修改当前数据。
- 最终确认页明确“当前数据将被备份后替换”，列出申请和附件数量。
- 成功后要求重新加载应用并提供核对清单；失败后说明是否已自动回滚及当前可用备份。

## 17. 通知、PWA 与离线草稿

### 17.1 提醒层级

提醒渠道按可靠性和边界说明：

1. 站内“今日”和日历始终可用。
2. M1 即提供 ICS 导出，由系统日历负责应用关闭后以及手机侧的可靠提醒。
3. M3 的浏览器通知仅在用户授权且运行环境允许时可用，不承诺应用关闭后的可靠投递。

产品不得宣传后台邮件、短信或微信提醒。

### 17.2 权限请求

不在首次打开页面时弹出浏览器权限。只有用户在设置中点击“开启浏览器通知”后才调用权限 API，并先用应用内说明解释用途。

权限状态显示为未请求、已允许、已拒绝、浏览器不支持。已拒绝时提供浏览器设置指引，不反复弹窗。

### 17.3 三类草稿与断连行为

三类草稿必须使用不同名称和入口：

- `EditorRecoveryDraft`：M1 起保存在固定 origin IndexedDB，仅保护长文本未成功保存的内容；成功持久化后清除，不是正式数据且不进入备份。M1 不使用 Service Worker，也不据此承诺离线创建。
- `OfflineCaptureDraft`：M3 起保存在同一 fixed origin IndexedDB，仅用于本地服务断连时的快速创建；重连后逐条确认写入，不进入备份。
- `CaptureDraft`：保存在 SQLite 当前数据 generation，用于在线粘贴或 AI 提取后的待确认结构化结果，属于可备份的本地数据。

设置页分别显示两类 IndexedDB 草稿的数量、最近更新时间和清理入口，不能把它们或 SQLite `CaptureDraft` 合并为一种“草稿”。

连接本地服务中断时：

- 已加载正式数据保持只读并显示可能过期的时间。
- M3 用户可以创建 `OfflineCaptureDraft`，草稿顶部持续显示“尚未写入正式数据”。
- 重连后展示草稿列表，让用户逐条确认、合并或丢弃。
- 如果目标申请同时被修改，展示字段差异，默认不覆盖数据库新值。

端口被其他程序占用时，启动页必须停止并提示释放 `3210` 端口；不得静默切换端口，否则已安装 PWA、Service Worker 与 IndexedDB 草稿会变成另一个 origin 下的数据。

## 18. AI 辅助体验

### 18.1 配置

设置项包含兼容接口地址、模型名和 API Key。Key 字段只显示“已保存/未配置”，不提供明文回显或复制。删除配置需要确认，但不影响基础规则解析。

未配置时，界面使用“智能提取（基础）”；配置后额外显示“使用 AI 完善”。不得用禁用整个录入入口的方式强迫用户配置。

### 18.2 发送与确认

每次调用 AI 前展示：将发送的内容预览、目标接口域名、模型名，以及“不会发送现有私人备注”的默认边界。用户可以缩减内容后再发送。

粘贴 URL 本身只填充来源字段，应用不会在后台抓取网页。规则提取处理用户实际粘贴的文字；只有用户在发送预览中明确确认的文字才可交给 AI 接口。

结果以字段建议呈现：原值、建议值、接受/忽略。支持逐项接受和全部接受，但“全部接受”不能自动保存正式实体；最终仍需点击创建或保存。

错误态区分网络失败、鉴权失败、额度/限流、无法解析。任何失败都提供“继续手工填写”，不得阻断核心流程。

## 19. 状态、空态与错误态

### 19.1 通用状态模型

每个异步区域必须实现以下适用状态：初始、加载中、有数据、真实空态、筛选空态、保存中、部分失败、完全失败、无权限/不可用。不得用永久旋转图标代替超时和恢复路径。

- 首次加载使用与最终布局接近的骨架；后台刷新保留旧内容并显示轻量状态。
- 超过 10 秒仍未完成的操作显示当前步骤、取消（安全时）和查看详情。
- 重试必须幂等；用户无法判断是否保存成功时，界面不得鼓励重复提交。

### 19.2 常见错误与恢复动作

| 场景 | 必须说明 | 主要操作 | 数据保护 |
| --- | --- | --- | --- |
| 本地服务断开 | 正式编辑暂不可用 | 重新连接 | 保留未提交输入为草稿 |
| 数据库被占用 | 哪个操作无法完成 | 重试 | 不覆盖数据库，不反复写入 |
| 磁盘空间不足 | 保存/附件/备份未完成 | 打开数据目录或重试 | 保留旧数据与上一备份 |
| 自动保存失败 | 具体字段仍未保存 | 重试保存 | 页面内保留输入，离开前提示 |
| 附件校验失败 | 文件名与失败原因 | 重新选择 | 不登记半复制附件 |
| 附件缺失/损坏 | 业务记录仍安全 | 从备份恢复 | 页面其余内容可继续访问 |
| 导入失败 | 是否已整体回滚 | 返回预览 | 保留列映射和错误报告 |
| 备份校验失败 | 该包不可用于恢复 | 选择其他备份 | 不修改当前数据 |
| 迁移失败 | 当前版本是否仍可启动 | 恢复上一版本 | 使用迁移前备份 |
| AI 调用失败 | 外部功能失败，核心功能正常 | 手工填写 | 不丢表单，不自动重发 |

技术错误码可以放在“详细信息”折叠区并支持复制，但标题和主要说明必须是用户可理解的中文。

### 19.3 成功反馈

- 自动保存不反复弹出提示条，只更新局部保存状态。
- 创建、归档、删除、恢复、导入和备份使用明确成功反馈。
- 有撤销能力时优先提供撤销；无撤销能力时在执行前确认，不在执行后只说“成功”。

## 20. 表单、自动保存与确认

### 20.1 验证时机

- 必填和格式验证在字段失焦时出现，提交时汇总；输入尚未完成时不连续报错。
- 错误显示在字段附近，并在提交失败时把焦点移到第一个错误；顶部摘要链接到所有错误。
- 用户输入永不因验证失败被清空。
- 日期歧义、URL 无效、重复记录属于需要说明的警告；只有破坏数据一致性的条件才阻止保存。

### 20.2 自动保存

- 短字段停止输入 600ms 后排队保存；同一实体的写入按顺序提交。
- 长文本使用本地草稿即时保护，停止输入 1 秒后保存正式版本。
- 页面关闭前仍有未提交写入时，先尝试完成；不能完成则显示离开确认。
- 多字段相关变更（下一步与等待、归档原因、阶段与时间线）必须通过显式确认和单事务提交，不拆成若干自动保存请求。

### 20.3 破坏性确认

确认框标题必须写明对象与动作，例如“永久删除「字节跳动 · 后端开发工程师」？”。正文说明是否可恢复、关联影响和备份情况。

“取消”保持安全且易发现；危险操作使用明确文字，不用泛化的“确定”。首次聚焦不得落在永久删除按钮上。

## 21. 视觉与组件原则

### 21.1 视觉方向

- 克制、清晰的效率工具风格，避免游戏化、强烈庆祝、倒计时恐吓和大面积高饱和状态色。
- 信息密度在桌面上适中偏高，但主要行动和风险层级必须清楚；长文本保持舒适行宽。
- 浅色、深色和跟随系统三种主题使用同一语义色映射。

### 21.2 状态表达

- 主阶段同时显示固定文字和可区分图标/形状；颜色只是辅助。
- 优先级始终写“高/中/低”，不能只显示红黄绿点。
- 待补、等待、逾期、冲突是不同语义，图标和文案必须不同。
- 成功、警告、错误、信息使用一致组件；不要用红色表达普通的“拒绝”历史事实而造成持续告警感。

### 21.3 密度与层级

- 页面只保留一个视觉主操作；同一区域的次要操作不超过两个，其余进入明确命名的菜单。
- 卡片摘要不展示完整 JD 或复盘；长内容只在详情中展开。
- 表单分组标题描述用户任务，例如“下一步怎么推进”，不用数据库字段名。

## 22. 无障碍要求

实现目标为 WCAG 2.2 AA，并至少满足：

### 22.1 键盘与焦点

- 所有功能可以仅使用键盘完成；看板拖动有“移动到阶段”菜单，附件拖放有文件选择按钮。
- 页面首次加载焦点不被强制移动；打开对话框后焦点进入标题或第一个字段并被限制在对话框内，关闭后回到触发元素。
- 提供“跳到主要内容”链接；导航、主内容、搜索和补充区域使用语义化 landmark。
- 焦点样式在浅色和深色主题均清楚，不能被 `outline: none` 无替代地移除。

### 22.2 颜色、对比度与文本

- 普通文字与背景对比度至少 4.5:1，大号文字至少 3:1；控件边界和焦点指示至少 3:1。
- 所有颜色状态同时有文字、图标或形状；图表提供数据表和可读标签。
- 正文支持放大至 200% 且不丢失功能；避免固定高度截断用户内容。

### 22.3 控件与动态反馈

- 触屏目标至少 44×44 CSS px；桌面密集表格中的小控件也应提供足够间距或扩展点击区域。
- 图标按钮必须有可访问名称；装饰图标对辅助技术隐藏。
- 保存结果、错误和异步完成使用适度的 `aria-live`；输入每个字符时不得重复播报保存中。
- 拖动、排序和阶段变化完成后向屏幕阅读器播报结果和撤销方式。
- 遵循“减少动态效果”系统设置，关闭非必要位移和过渡；没有闪烁内容。

### 22.4 编辑器和日期控件

- 富文本工具栏可用方向键导航，格式状态可被读出，并提供纯文本粘贴能力。
- 日期选择器支持键盘输入和本地化格式；即使弹出日历不可用，也能直接输入有效日期。
- 错误信息通过程序化关系关联字段；占位符不能替代可见标签。

## 23. 文案规范

### 23.1 基本原则

- 使用术语表中的统一名词：“申请”“阶段”“下一步行动”“复查日期”“归档”“删除”“永久删除”。
- 按“发生了什么—有什么影响—下一步做什么”写错误，不用“未知错误”“操作失败”单独结束。
- 用明确动词命名按钮，例如“创建申请”“移至面试中”“导出 12 条申请”，避免只写“确定”“提交”。
- 时间和数量尽可能具体；“即将到期”必须同时显示准确日期时间。
- 不责备用户，不使用“你忘了”“你失败了”；使用“这条申请还缺少下一步”。
- 不制造虚假紧迫感，不使用连续打卡、失去进度或惩罚式措辞。

### 23.2 状态文案样例

| 场景 | 推荐文案 | 禁止倾向 |
| --- | --- | --- |
| 待补 | 这条申请还缺少下一步 | 你还没有完成任务 |
| 等待复查 | 等待结果，9月12日复查 | 无事可做 |
| 事件结束 | 面试已结束，要确认结果或更新进度吗？ | 已自动进入下一轮 |
| 自动保存失败 | 尚未保存。你的输入仍保留在此设备，可重试。 | 保存失败（500） |
| 归档 | 归档后将从活跃看板移除，资料和历史仍保留 | 删除这条申请 |
| 永久删除 | 永久删除后无法从回收站或应用内恢复 | 确定吗？ |
| AI 草稿 | 已生成建议，请确认后保存 | AI 已完成更新 |
| ICS | 导出是单向的；在系统日历中修改不会回写 | 已同步日历 |

### 23.3 敏感边界文案

- AI 发送前写清目标域名和发送内容，不使用笼统的“同意隐私政策”。
- 普通备份写明“可能包含 JD、面试记录和附件”；加密备份写明“密码无法找回”。
- 分享预览写明默认排除的私人字段，并让用户逐项确认新加入的字段。
- 日志和诊断入口说明“不包含正文和 API Key”，若实际实现无法保证则不得使用该承诺。

## 24. 关键端到端流程验收

### 24.1 从机会到下一步

1. 用户从任意页面按 `N`。
2. 输入公司和岗位并创建。
3. 系统提示缺少下一步。
4. 用户设置“今晚完善简历”，可选截止时间。
5. 今日页面出现该行动，申请卡显示机会池和下一步。

验收重点：全程不要求填写批次或 JD；创建、行动和时间线数据一致。

### 24.2 收到面试通知

1. 用户从申请详情创建面试事件，填写时间和会议链接。
2. 系统显示已有事件冲突，用户确认仍然保存。
3. 今日首页和日历同时显示面试及冲突标记。
4. 用户导出 ICS，在预览中确认不包含私人复盘。
5. 面试结束后系统询问结果，但阶段保持不变，直到用户确认更新。

验收重点：冲突不阻断保存；没有自动阶段推进；ICS 使用稳定 UID。

### 24.3 等待结果

1. 用户完成当前下一步。
2. 选择“进入等待中”，填写“等待一面结果”和复查日期。
3. 申请卡显示等待文案，不再显示已完成行动。
4. 到复查日期后进入今日的等待复查区。
5. 用户选择继续等待并设置新日期，或设置新的下一步。

验收重点：下一步和等待不能并存；复查日期必填且更新有时间线。

### 24.4 招聘会转申请

1. 用户创建招聘会并添加多个目标公司/岗位。
2. 现场记录笔记；会后对某目标点击创建申请。
3. 快速创建预填公司、岗位和招聘会来源。
4. 重复检查后创建，招聘会和申请互相可跳转。

验收重点：未选择的目标不自动变成申请；来源关联不是自由文本副本。

### 24.5 导入现有表格

1. 用户选择 CSV/XLSX（仅导入；产品不提供 XLSX 导出）。
2. 完成列映射并查看日期解析、错误与重复项。
3. 修正阻塞问题后确认导入。
4. 系统在一个事务中写入，并报告结果。
5. 缺少行动的活跃记录进入今日待补区；用户可以撤销本次导入。
6. 用户可将结果导出为 CSV，当前筛选与全部申请均可用。

验收重点：预览前不写数据；失败整体回滚；原文件内容不进入日志；导出只有 CSV 且通过公式注入防护。

### 24.6 备份恢复

1. 用户创建包含附件的完整备份，可选密码。
2. 选择该包恢复，系统先校验并展示摘要。
3. 用户确认后，系统创建当前快照并在临时位置恢复。
4. 一致性检查通过后切换并重新加载。
5. 用户按清单核对申请、事件、资料和附件。

验收重点：错误密码或损坏包不修改当前数据；中途失败自动回滚。

## 25. 设计与实现交付检查表

每个页面进入开发前，设计稿或实现说明必须回答：

- 页面的唯一主要任务是什么？
- 初始、加载、有数据、真实空态、筛选空态、部分失败和完全失败分别怎样显示？
- 桌面、中等宽度、窄屏和 200% 缩放下如何重排？
- 键盘路径、焦点返回、屏幕阅读器名称和拖放替代是什么？
- 自动保存、失败保留和离开页面时如何处理？
- 是否涉及删除、覆盖、外部发送或不可逆操作；确认文案是什么？
- 该行为对应哪个 PRD `FR-Mx-xx`，由哪类自动化测试覆盖？

若实现需要改变本文定义的导航、状态语义、关键流程或敏感数据边界，应先更新 PRD 与本规格，再修改代码。
